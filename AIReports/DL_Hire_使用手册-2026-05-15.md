## 1. 产品概述

DL Hire 是一个覆盖蓝领员工 **从招募到上岗全生命周期** 的数字化入职管理平台，面向菲律宾、马来西亚、泰国三个东南亚市场。

### 核心流程

```
Agency协同 → 候选人管理 → 面试管理 → 极速审批 → 电子入职 → 培训考核 → EHS合规
```

### 相比竞品 KonekBuhay 的差异化优势

| 能力 | DL Hire | KonekBuhay |
|------|---------|-------------|
| 候选人管理 (CTS) | ✅ | ✅ |
| Agency（劳务中介）协同 | ✅ 独家 | ❌ |
| 在线面试 + 技能评估 | ✅ | ❌ |
| 移动端审批流 | ✅ | ❌ |
| 电子合同签署 | ✅ | ❌ |
| EHS 安全培训模块 | ✅ 独家 | ❌ |
| 多语言/多国合规 | ✅ PH/MY/TH | ❌ 仅PH |

## 3. 快速启动

### 环境要求

| 依赖 | 版本 |
|------|------|
| Rust | 1.70+ |
| Node.js | 18+ |
| npm | 9+ |

### 启动步骤

**1. 启动后端 API 服务**

```bash
cd /home/wang/wk/code/dl-hire/backend

# 开发模式（自动编译 + 启动）
cargo run

# 生产模式
cargo build --release
./target/release/dl-hire
```

后端监听 `http://localhost:3200`。首次运行自动创建 `dl_hire.db` 数据库文件和所有表结构。

环境变量配置：

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `DL_HIRE_DB` | `dl_hire.db` | 数据库文件路径 |
| `DL_HIRE_JWT_SECRET` | `dl-hire-jwt-secret-2026` | JWT 签名密钥（生产环境务必修改） |

**2. 启动前端界面**

```bash
cd /home/wang/wk/code/dl-hire/frontend
npm install
npm run dev
```

前端运行在 `http://localhost:5173`。启动后会自动将 `/api/*` 请求代理到后端。

**3. 验证**

```bash
# 测试后端健康检查
curl http://localhost:3200/api/v1/health
# 应返回: OK

# 前端访问
# 浏览器打开 http://localhost:5173
```

## 5. 功能使用指南

### 5.1 注册与登录

**注册账号：**
1. 访问 `http://localhost:5173/register`
2. 填写：姓名、邮箱、密码（至少6位）、角色、公司ID（可选）
3. 点击注册，成功后自动跳转到控制台

**登录：**
1. 访问 `http://localhost:5173/login`
2. 输入邮箱和密码
3. 点击登录

首次使用时先注册一个 `admin` 角色账号，用于后续管理。

### 5.2 控制台 (Dashboard)

登录后默认进入控制台，展示：

- **总候选人数** — 系统中所有候选人总量
- **新候选人** — 状态为 `new` 的候选人
- **已录用** — 状态为 `hired` 的候选人
- **已拒绝** — 状态为 `rejected` 的候选人
- **按状态分布表** — 各状态候选人数量明细

数据来源于后端统计 API，实时更新。

### 5.3 候选人管理

**候选人列表：**
1. 左侧菜单点击 **Candidates**
2. 表格展示所有候选人，支持：
   - 按状态筛选（new/screened/interviewing/offered/hired/rejected）
   - 按姓名/电话/邮箱搜索
   - 点击"View"查看详情
   - 点击"Delete"删除

**新建候选人：**
1. 在候选人列表页点击 "New Candidate"
2. 填写候选人完整简历信息（见下方字段说明）
3. 点击 Create

**候选人简历字段：**

| 分类 | 字段 | 说明 |
|------|------|------|
| **基本信息** | name, phone, email | 姓名（必填）、电话（必填）、邮箱 |
| | id_number, country_code | 身份证/护照号、国家代码（PH/MY/TH） |
| | date_of_birth, gender, nationality | 出生日期、性别、国籍 |
| **地址信息** | address, city, province, postal_code | 详细地址、城市、省份、邮编 |
| **教育背景** | education_level, education_school | 学历层次、毕业学校 |
| | education_major, education_year | 专业、毕业年份 |
| **工作经验** | work_experience_years | 工作年限（整数） |
| | previous_employer, previous_position | 前雇主、前职位 |
| | previous_duration, previous_duties | 工作时间段、工作职责 |
| **技能资质** | skills (JSON数组) | 技能标签，如 `["welding","assembly"]` |
| | languages, certifications | 语言能力、资质证书 |
| **紧急联系** | emergency_contact_name | 紧急联系人姓名 |
| | emergency_contact_phone | 紧急联系人电话 |
| | emergency_contact_relation | 与候选人关系 |
| **其他** | resume_text, resume_file_url | 简历文本、简历文件URL |
| | profile_photo_url | 头像URL |
| | source, notes | 来源（direct/agency/referral）、备注 |

**导入候选人 (CSV)：**
适用于批量导入。支持的 CSV 格式：

```
name,phone,email,id_number,country_code,skills,source,notes
Maria Santos,09171234567,maria@example.com,PH987654321,PH,forklift;packaging,direct,Experienced operator
Juan Cruz,09189876543,juan@example.com,PH123456789,PH,welding;assembly,agency,
```

导入规则：
- 首行为列名称（自动跳过）
- `skills` 字段用分号 `;` 分隔多项技能
- 自动去重：同电话/邮箱的候选人不会重复导入
- 导入结果会显示成功数和错误详情

**候选人详情页：**
- 查看完整信息
- 修改候选人状态（下拉选择）
- 编辑基本信息
- 查看关联的面试记录
- 查看活动时间线

### 5.4 面试管理

**安排面试：**
1. 左侧菜单点击 **Interviews**
2. 点击 "Schedule Interview"
3. 填写：候选人ID、岗位名称、面试时间
4. 点击 Create

**面试签到：**
在面试列表点击 "Check-in"，记录签到时间。

**面试评估：**
1. 面试列表中找到 Scheduled 状态的面试
2. 点击 "Evaluate"
3. 填写：
   - **技能评分 (JSON)** — 如 `{"welding": 85, "assembly": 90}`
   - **综合得分** — 0-100
   - **评语**
   - **结果** — Pass / Fail
4. 点击 Save Evaluation

### 5.5 审批管理

适用于经理（Manager）或管理员在移动端/桌面端进行录用审批。

**创建审批：**
1. 选择需要录用的候选人
2. 通过 API 或未来前端功能创建审批请求
3. 系统自动分配审批人

**处理审批：**
在 Approvals 页面查看待审批列表：

| 操作 | 效果 |
|------|------|
| **Approve** | 批准录用 → 候选人状态自动变为 `offered` |
| **Reject** | 拒绝录用 → 候选人状态不变 |
| **Transfer** | 转审给其他人 → 原审批标记为 transferred，创建新审批 |

每项操作都会记录到审计日志。

### 5.6 劳务中介 (Agency) 门户

**我的候选人：**
- 仅展示当前中介导入的候选人
- 状态实时追踪

**批量导入：**
1. 在 My Candidates 页面的 Batch Import 区域
2. 粘贴 CSV 数据（格式同候选人导入）
3. 点击 Import My Candidates
4. 系统自动设置 `agency_id` 和 `source='agency'`

### 5.7 员工管理

**转为正式员工：**
前提：候选人状态必须为 `offered`（已通过审批）

1. 左侧菜单点击 **Employees**
2. 点击 "Hire from Candidate"
3. 选择 Offered 状态的候选人
4. 填写：员工编码（留空自动生成）、部门、岗位
5. 点击 Create Employee
6. 系统自动将候选人状态更新为 `hired`

### 5.8 培训课程管理

**创建课程：**
通过 API 创建：
```bash
curl -X POST http://localhost:3200/api/v1/courses \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "title": "PH OSH 8-Hour Safety Training",
    "course_type": "ehs",
    "country": "PH",
    "mandatory": 1,
    "pass_score": 80
  }'
```

课程类型：
- `onboarding` — 入职培训
- `ehs` — EHS 安全培训
- `skills` — 技能培训
- `compliance` — 合规培训

**培训记录：**
- 开始培训：`POST /api/v1/training/start`
- 完成培训：`POST /api/v1/training/complete`
- 查询记录：`GET /api/v1/training/records`

### 候选人状态自动流转

系统在关键节点自动更新候选人状态：

| 触发点 | 状态变更 | 说明 |
|--------|---------|------|
| 候选人创建 | `→ new` | 新建候选人默认为"新申请" |
| 面试评估结果为 `pass` | `→ offered` | 面试通过后自动标记为"已录用待审批" |
| 审批通过 | `→ offered` | 经理批准录用 |
| 入职确认（创建员工） | `→ hired` | 完成入职手续后转为"已入职" |

### API 认证方式

所有需要认证的端点需要在请求头中携带 JWT Token：

```
Authorization: Bearer eyJ0eXAiOiJKV1QiLCJhbGciOiJIUzI1NiJ9...
```

Token 有效期 24 小时，过期后可通过 `POST /auth/refresh` 刷新。

### 状态码

| 状态码 | 说明 |
|--------|------|
| 200 | 成功 |
| 400 | 请求参数错误 |
| 401 | 未认证/Token 无效 |
| 404 | 资源不存在 |
| 500 | 服务器内部错误 |

## 8. 常见问题

### Q: 启动后端提示端口被占用？
```bash
fuser -k 3200/tcp  # 释放端口
cargo run
```

### Q: 忘记管理员密码？
直接删除数据库文件重建（开发环境）：
```bash
rm -f backend/dl_hire.db && cargo run
```
然后重新注册管理员账号。

### Q: 前端页面白屏/API 请求失败？
1. 确认后端正在运行：`curl http://localhost:3200/api/v1/health`
2. 确认前端代理配置：`vite.config.ts` 中 `proxy.target` 指向 `http://localhost:3200`
3. 检查浏览器控制台是否有 CORS 错误

### Q: 如何切换数据库？
```bash
export DL_HIRE_DB=/path/to/custom.db
cargo run
```

### Q: 角色权限不足？
当前角色权限检查逻辑在 `lib.rs` 中各处理器函数开头：
```rust
auth::check_role(&auth_user, &["admin", "recruiter"])?;
```
如需调整，修改对应 roles 列表即可。

### Q: 如何查看审计日志？
审计日志自动记录所有关键操作，可通过以下方式查看：
1. 候选人详情页的 Timeline 标签
2. 直接查询数据库：`sqlite3 dl_hire.db "SELECT * FROM audit_logs ORDER BY created_at DESC LIMIT 20;"`
