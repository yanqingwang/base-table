## 三、本地确认（B 端商业控制台全链路，人工/浏览器）

### 环境准备与登录态

按「一、本地启动方式」起商业版后端（5000 端口），员工/顾客登录态用 `/api/auth/wechat-login` 身份头直登（见一章第 4 节）。

### 浏览器全链路（应在浏览器实测并截图）

1. 打开 `http://127.0.0.1:5000/merchant/<mid>/console?token=<员工JWT>` → **经营看板**：KPI、近7天趋势、卡密账本概况正常渲染
2. **卡密中心**：填名称/面额/数量/有效期 → 生成 → 明文兑换码弹层（仅此一次）→ 导出 CSV → 报表与批次列表即时刷新
3. 顾客侧闭环（curl 或任意已登录顾客身份）：
   ```bash
   CTOK=<顾客JWT>
   curl -X POST localhost:5000/api/redeem  -H "Authorization: Bearer $CTOK" \
        -H 'Content-Type: application/json' -d '{"code":"<明文码>","idempotencyKey":"t1"}'
   curl -X POST localhost:5000/api/spend   -H "Authorization: Bearer $CTOK" \
        -H 'Content-Type: application/json' -d '{"cardNo":"<卡号>","amountCents":2000,"idempotencyKey":"t2"}'
   curl localhost:5000/api/wallet -H "Authorization: Bearer $CTOK"
   ```
   预期：兑换入账面额 → 消费返回 `receiptHmac` → 钱包余额正确；重复同幂等键提交不重复扣款。
4. **对账中心**：填平台令牌（本地=启动时的 `PLATFORM_ADMIN_TOKEN` 值）→ 保存 → 立即对账 → 预期 0 差异、数据准确率 100%；全局账本可见成对借贷分录且余额快照正确。

### 边界用例（可选，curl 快测）

| 用例 | 预期 |
|---|---|
| `POST /api/redeem` 不带 token | 401 |
| `code` 传 dict / 空 | 400 |
| 同一兑换码重复兑换 | 409 已被兑换 |
| 消费金额 > 余额 | 409 余额不足 |
| `GET /api/platform/recon` 无令牌 | 403 |
| `X-Platform-Token` 错值 | 403 |

## 五、已知坑位（测试时注意）

- 商业版 flask 与 Demo commercial 的卡密表**同名不同列**（snake/camelCase）——本地把两个服务指向同一个库会互相打碎 schema
- commercial 本地跑测试用自带 `.venv`（SQLAlchemy 2.0）；flask 用 `/home/wang/wk/tmp/flask-venv`（SQLAlchemy 1.4）
- 平台端点令牌：flask 读 `PLATFORM_ADMIN_TOKEN` 环境变量（空=全部 403）；commercial 同名变量 + `X-Platform-Token` 头（网页登录路径不受影响）
- 对账"数据准确率"结单后**不会**恢复——历史出过差异的批次永久计入分母，属设计行为
