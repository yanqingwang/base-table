# 登录验证功能 · 验收说明

- 日期：2026-09-10
- 仓库：`card-counter-commercial`（商业化演示/主开发仓，自包含）
- 范围声明：**仅改动本仓**，未触碰顾客端小程序 `card-counter-miniapp` 与生产网页后端 `card-counter-flask`

---

## 一、需求与实现结论

| 需求 | 实现 | 状态 |
|---|---|---|
| 增加登录验证功能 | 前端登录闸门 + 后端 Bearer 会话校验，未登录不可进入业务页 | ✅ |
| 用户名 + 密码登录 | `POST /api/auth/login`（PBKDF2-HMAC-SHA256 + 不透明 Bearer token，12h、可吊销） | ✅ 复用并回归 |
| 微信公众号验证登录 | 公众号网页授权 OAuth2 全链路（授权 URL → code → openid → 账号 → token） | ✅ 新增 |
| 「基于验证」 | 请求身份由 token 解析（商户/平台/顾客三类），权限与数据按账号隔离 | ✅ |

**设计原则**：登录态是「验证」的唯一凭据来源；既有演示头（`X-Merchant-Id` / `X-Staff-Id` / `X-Platform-Admin` / `X-Customer-*`）仅在显式「演示模式」下使用，登录后一律走 `Authorization: Bearer`。

## 二、后端实现

### 2.1 新增服务 `services/wechat_auth.py`
- `config_view()`：下发前端配置（`configured/appId/scope/redirectUri/demoEnabled`），**绝不含 AppSecret**
- `build_authorize_url(redirect, scope)`：生成 `open.weixin.qq.com/connect/oauth2/authorize` 跳转地址
- `new_state()` / `verify_state()`：`ts.hmac16` 格式，HMAC-SHA256 签名 + 10 分钟时效 → 防 CSRF / 防重放
- `exchange_code(code)`：`sns/oauth2/access_token` 换 openid；`snsapi_userinfo` 时再取昵称（纯 stdlib `urllib`，零新依赖）
- `demo_exchange(code)`：未配置公众号时的演示降级，由任意标识派生稳定 openid（`sha256` 前 24 位）

### 2.2 扩展 `services/auth.py`
- 抽出 `issue_token()`，`authenticate()` 与微信登录共用
- **新增 `wechat_login()`**：按 openid find-or-create `Customer` → find-or-create `UserAccount(actorType="customer")` → 签发 token（幂等：同一 openid 复登不重复建号）
- `actor_view()` 新增 `customer` 分支（返回 `customerId/openid/displayName/role`）
- 账号类型从「platform_admin / staff」扩展为「+ customer」，兑现模型注释里的「预留扩展」

### 2.3 新增/改造路由 `routes/__init__.py`

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/auth/wechat/config` | 公众号登录配置（无敏感字段） |
| POST | `/api/auth/wechat/authorize` | 生成授权跳转 URL + state |
| GET/POST | `/api/auth/wechat/callback` | 回调：校验 state → code 换 openid → 签发 token |
| POST | `/api/auth/wechat/demo` | 演示微信登录（未配置公众号时） |
| GET | `/api/auth/demo-accounts` | 演示账号提示（仅演示模式开启时返回） |

- `_customer_id()` / `_customer_openid()` 增加 **Bearer 回退**：无演示头时由 customer token 解析身份与 openid
- 不串味保证：staff token 调顾客接口仍报「缺少 X-Customer-Id」（400），不会误判为顾客

### 2.4 生产配置（启用真实公众号登录）
在部署环境设置，无需改代码：

```
WECHAT_OAUTH_APPID      公众号 AppID
WECHAT_OAUTH_SECRET     公众号 AppSecret（仅服务端）
WECHAT_OAUTH_REDIRECT   网页授权回调（须在公众号「网页授权域名」内）
WECHAT_OAUTH_SCOPE      默认 snsapi_base；需昵称用 snsapi_userinfo
WECHAT_OAUTH_ALLOW_DEMO 生产建议设 0（关闭演示登录与演示账号提示）
```

未配置时自动降级为「演示模式」，演示站开箱可用。

## 三、前端实现（`web/`）

- **登录闸门**（`index.html` + `styles.css`）：全屏遮罩，双 Tab —— **账号密码登录** / **微信登录**
- `app.js`：
  - token 持久化 `localStorage["cc.auth.v1"]`；`api()` 自动注入 `Authorization: Bearer`
  - 401 自动清理登录态并弹回闸门；启动时 `GET /api/auth/me` 校验并恢复会话
  - 微信回调：解析 `?code=&state=` → `POST /api/auth/wechat/callback` → 建会话并清理地址栏
  - **角色由账号推导**：platform_admin→平台超管 · staff(isOwner/有 issue_card)→店长 · staff→核销员 · customer→顾客；登录后隐藏「演示身份切换」
  - 顶栏用户区显示「角色 + 姓名 + 所属企业 + 退出登录」
  - 保留**「以演示模式进入（免登录）」**入口，既有 demo 体验不被破坏
- favicon 改内联 SVG，消除 404 噪音

## 六、已知限制与后续

1. **公众号登录需真实 AppID + 授权域名**：当前为演示降级；配置环境变量即切换真实链路（代码零改动）。
2. **令牌为不透明 DB 会话**（非 JWT）：可即时吊销，适合本项目；如需跨服务可换 JWT。
3. 演示模式下 `/api/auth/demo-accounts` 会返回演示初始密码，**生产请设 `WECHAT_OAUTH_ALLOW_DEMO=0`** 关闭。
4. 未做：登录失败次数限流、短信验证码、顾客手机号绑定（可作后续）。
5. 未部署：`cardcount-web` 非 push 自动部署，需在云托管控制台手动重新部署后线上可见。
