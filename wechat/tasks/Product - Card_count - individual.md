## 📋 一、需求最终确认汇总

|模块|你的决策|开发要点|
|---|---|---|
|**冷启动**|有示例数据引导|预置3-5条示例配额，展示完整功能，用户可删除或修改|
|**签到路径**|先选商家 → 点签到 → 自动扣减该商家下默认配额的1次|需要“商家选择器”页面/弹窗，支持修改扣减次数，支持**当天反签到（撤销）**|
|**学习建议算法**|结合周末/寒暑假权重，综合计算|首页显示全局概览，详情页显示单条配额的每日建议 + **“建议间隔X天参加一次”**|
|**冲突处理**|以时间戳（`updatedAt`）大的为准|合并逻辑使用 `updatedAt` 比对|
|**同步时机**|启动时自动拉取 + 下拉刷新手动触发|两者都要|
|**首次登录恢复**|提示用户“发现云端备份，是否恢复？”|弹窗确认后再下载覆盖本地|

## 🔄 四、核心流程详细设计

### 1. 签到流程（关键）

text

用户进入签到页
    ↓
展示所有“进行中”的配额列表（按商家分组）
    ↓
用户选择一个配额（商家/事项）
    ↓
点击“签到”按钮
    ↓
【默认扣减1次】，弹窗显示：
   "本次签到：XX商家 - XX事项，扣减 1 次，剩余 X 次"
   并提供【修改次数】和【确认】按钮
    ↓
用户确认后：
   a. 更新本地 quota 的 usedTimes +1
   b. 新增一条 checkin 记录
   c. 更新 updatedAt 时间戳
   d. UI 立即刷新
   e. 异步调用云数据库同步
    ↓
当天若误签，可进入【今日签到记录】列表，点击【撤销】按钮
   → 反向操作：usedTimes -1，删除 checkin 记录（或标记 isRevoked=true）

### 2. 学习建议算法（综合规划）

#### 全局概览（首页顶部）

- 汇总所有“进行中”配额的**总剩余次数**和**平均每天建议次数**
    
- 提示：“综合剩余 X 次，建议平均每 Y 天参加一次”
    

#### 单条配额详情（详情页）

- 计算逻辑：
    
    1. 计算剩余天数 = `expireDate` - 今天
        
    2. 若剩余天数 ≤ 0，提示“已过期”
        
    3. 计算剩余次数 = `totalTimes - usedTimes`
        
    4. 考虑权重：
        
        - 统计剩余天数内包含的**周末天数 × 2** + **工作日天数 × 1** + **节假日天数 × 1.5**
            
        - 加权总负荷 = 剩余次数 / 加权天数总和
            
    5. 输出：
        
        - “建议每天完成 X 次”
            
        - “建议每 X 天参加一次”（取整：`Math.ceil(加权天数总和 / 剩余次数)`）

## ⚙️ 六、同步策略详细说明

### 启动时自动拉取 + 合并

text

onShow() / onLaunch() 触发
    ↓
读取本地数据
    ↓
判断：本地是否有数据？
    ├── 无数据（首次使用）
    │      ↓
    │   提示用户：“是否恢复云端备份？”
    │      ├── 是 → 拉取云端全部数据，写入本地
    │      └── 否 → 写入示例数据，开始使用
    │
    └── 有数据
           ↓
        后台拉取云端数据（静默）
           ↓
        按 `localId` 匹配，比对 `updatedAt`
           ├── 云端更新 → 覆盖本地
           └── 本地更新 → 保持本地，并推送到云端
           ↓
        合并完成后更新 `lastSyncTime`

### 下拉刷新手动触发

- 用户下拉页面时，显示刷新动画
    
- 执行完整合并逻辑（同上）
    
- 刷新完成后提示“已同步最新数据”
    

### 写操作同步

- 每次增/改/删操作后，立即写本地
    
- 异步调用云数据库 API（`add` / `update` / `remove`）
    
- 失败时在“我的”页面显示“有 X 条数据待同步”的红点提示
    
- 提供“重试同步”按钮

## ✅ 七、开发任务拆解（建议排期）

|阶段|任务|预估工时|
|---|---|---|
|**第一阶段（基础架构）**|云开发环境初始化、数据库集合创建、本地Storage工具类封装|0.5天|
|**第二阶段（配额管理）**|新增配额表单、配额列表展示、配额详情页、状态自动更新|1天|
|**第三阶段（签到核心）**|商家选择器、签到扣减逻辑、今日签到记录、反签到（撤销）|1.5天|
|**第四阶段（统计与建议）**|全局统计、学习建议算法、图表展示（可用 `wx-charts` 或 Canvas 手绘）|1天|
|**第五阶段（评价系统）**|评价列表、新增评价（打分组件）、满意度排序|0.5天|
|**第六阶段（同步与备份）**|启动拉取合并、下拉刷新、冲突处理、导出/导入备份|1天|
|**第七阶段（UI美化与测试）**|界面风格统一、空状态设计、示例数据、真机测试|1天|

**总预估工时**：约 6.5 天（不含 UI 设计稿时间）
