## 4.1 HCM 集成总览

### 架构原则

做集成前，先刻在脑子里一句话：**HCM 是事实源，HRSD 是交互层。**

人员数据（组织、岗位、成本中心、汇报关系）统一在 HCM 中维护，HRSD 只读同步，所有修改操作回写 HCM。

```
┌─────────────────────────────────────────────────────────┐
│  HCM 人员数据权威源                                        │
│  (Workday / SuccessFactors / Oracle HCM)                  │
└──────────┬──────────────────────────────────────┬─────────┘
           │ SOAP / REST / SFTP                    │ Webhook
           ▼                                       ▼
┌─────────────────────────────────────────────────────────┐
│  ServiceNow HRSD 服务交互层                                │
│  ┌─────────┐ ┌──────────┐ ┌─────────┐ ┌───────────┐    │
│  │ 案例管理  │ │  知识库   │ │ 自助门户 │ │ AI Agent  │    │
│  └─────────┘ └──────────┘ └─────────┘ └───────────┘    │
└─────────────────────────────────────────────────────────┘
           │
           ▼
     全体员工统一的员工体验
```

### 数据流向决策矩阵

| 数据类型 | 方向 | 实时性要求 | 推荐方式 |
| --- | --- | --- | --- |
| 员工主数据（HR Profile） | HCM → HRSD | 近实时（分钟级） | Store App + Webhook |
| 组织层级（Department） | HCM → HRSD | 每日同步 | 定时 Spoke |
| 薪酬数据 | HCM → HRSD | 只读 | HSDI（高级集成） |
| 休假申请 | 双向 | 实时 | HSDI |
| 入职/离职事件 | HCM → HRSD | 近实时 | Webhook + Flow |
| 案例数据回写 | HRSD → HCM | 按需 | Custom Spoke Action |

### ⚠️ 常见坑

- **双向同步冲突**：同一字段在两边都修改 → 必须设计"事实源"规则。HCM 字段以 HCM 为准，HRSD 独有字段（如案例状态）不回写
- **全量同步性能**：首次同步几十万员工时，Transform Maps 逐行处理极其缓慢。建议用分批导入 + `Import Set Row` 的批量模式
- **增量同步遗漏**：Webhook 丢事件时有发生。建议：增量定时同步兜底 + Webhook 做近实时触发，两条腿走路

## 4.2 Workday 集成 — 实操

### 三种方式选型决策树

```
你的场景是什么？
├── 只需要员工主数据同步（HR Profile）
│   └── ✅ 标准集成（Store App）—— 最快，30 分钟配完
├── 需要薪酬/假期/日历等高级功能
│   └── ✅ 高级集成 HSDI（需额外插件）
└── 需要自定义数据映射/回写 Workday
    └── ✅ Workday HR Spoke（Integration Hub）
```

### 方式一：标准集成（Store App）

这是最常用、最快速的方式。

#### 前置条件

| 项目 | 要求 |
| --- | --- |
| ServiceNow 版本 | Utah+（推荐 Vancouver+） |
| 插件 | `sn_hr_core`（HRSD 基础插件） |
| Workday 租户 | 正式租户或 Implementation 租户 |
| Workday API 用户 | 需要有 `Get Workers`、`Get Job Profiles` 等权限 |
| 网络 | ServiceNow 实例能访问 Workday SOAP API |

#### 导航

```
All → System Applications → All Available Applications → 搜索 "Workday HR"
```

或直接走 Store：

```
All → Store → 搜索 "Workday Standard Integration"
```

#### 步骤

**第 1 步：安装 Workday HR Spoke**

安装 Standard 版本（不要求 Integration Hub 订阅）。安装完成后，系统会自动创建：

- 连接器记录
- Transform Maps
- 导入集
- 调度作业

**第 2 步：配置认证**

```
All → Workday HR → Connection & Credentials
```

| 参数 | 说明 |
| --- | --- |
| Workday Tenant URL | `https://services.myworkday.com/` 或 `https://<tenant>.myworkday.com` |
| API Version | v38+（建议用最新稳定版） |
| Username | `integration_user@tenant` |
| Password | 对应密码 |
| ISU（Integration System User） | 需要授权以下领域：Worker Data: Get, Job Profile: Get, Organization: Get |

**第 3 步：配置主流程**

```
All → Workday HR → Main Flow Configuration
```

| 参数 | 推荐值 |
| --- | --- |
| 运行频率 | 每 4 小时一次（生产）；每 1 小时一次（上线初期） |
| 拉取对象 | 勾选 Workers、Job Profiles、Departments、Locations |
| 增量同步 | 开启（仅同步上次运行后有变更的数据） |

**第 4 步：配置 Webhook 事件**

```
All → Workday HR → Subscription Configuration
```

| 事件 | 用途 |
| --- | --- |
| CreateUser | 新员工入职 → 自动创建 HR Profile |
| Offboarding | 员工离职 → 标记 HR Profile 状态 |
| LeaveOfAbsence | 休假事件 → 触发案例 |
| JobChange | 岗位变更 → 更新 HR Profile |

**第 5 步：测试同步**

1. 手动运行主流程：
   ```
   All → Workday HR → Flow Configuration → 选择 Main Flow → Execute Now
   ```
2. 检查导入集：
   ```
   All → Load → 搜索 Import Set Row → 筛选 source = Workday HR
   ```
3. 验证 Transform Maps：
   ```
   All → System Import Sets → Transform Maps → 选择 Workday HR 相关 Map → Transform History
   ```
4. 检查 HR Profile 是否生成：
   ```
   All → HR Administration → HR Profiles → 搜索测试员工
   ```

#### ⚠️ 常见坑

- **Workday API 版本不兼容**：Workday v37 以下不支持某些字段。建议统一用 v38+
- **Transform Map 字段不对应**：Workday 返回字段名和 ServiceNow 预期字段名可能不匹配。在 Transform Maps 里手动做 Field Map 修正
- **Webhook 证书轮换**：Workday ISU 证书过期后 Webhook 静默失败。监控 `syslog` 中 `Workday` 相关 Error 日志
- **ISU 权限不足**：Workday 需要给 ISU 授权 `Worker Data: Get`、`Job Profile: Get`、`Organization: Get`、`Supervisory Organization: Get`，缺一不可

### 方式二：高级集成 HSDI

HSDI（HR Service Delivery Integration）是标准集成的增强版。

#### 插件安装

```
All → System Applications → Plugins → 搜索 "HR Service Delivery Integration"
```

插件 ID：`sn_hr_integration`

#### 激活的附加功能

| 功能 | 导航位置 | 说明 |
| --- | --- | --- |
| Total Rewards | `All → HR Administration → My Rewards` | 员工可见薪酬总包 |
| Holiday Calendar | `All → HR Administration → Holiday Calendar` | 同步 Workday 假期 |
| Payroll Discrepancy | `All → HR Administration → Payroll` | 薪资差异自动通知 |
| Time Off Request | `All → HR Administration → Time Off` | 员工在 ServiceNow 提交休假，回写 Workday |
| Legal Name Change | `All → My Profile → Legal Name` | 法定姓名变更流程 |

#### 配置要点

```
All → HR Administration → Integration Configuration
├── Holiday Calendar Sync → 选择 Workday 假期日历
├── Payroll Integration → 配置薪资文件映射
└── Time Off Mapping → 配置休假类型对应关系
```

### 方式三：Workday HR Spoke（Integration Hub）

适用于需要自定义逻辑的场景。

#### 前置条件

| 项目 | 要求 |
| --- | --- |
| Integration Hub 订阅 | 必须有 |
| Spoke 安装 | Store 安装 "Workday HR Spoke" |
| 自定义 Action | 可在 Flow Designer 中调用 |

#### 配置流程

**第 1 步：安装 Spoke**

```
All → Store → 搜索 "Workday HR Spoke" → Install
```

**第 2 步：配置连接**

```
All → Integration Hub → Connections → New → Workday HR
```

| 参数 | 说明 |
| --- | --- |
| Connection Alias | `workday_prod` |
| Auth Profile | 使用 OAuth 或 Basic Auth |
| Endpoint URL | Workday SOAP 或 REST 端点 |

**第 3 步：在 Flow Designer 中使用**

```
All → Process Automation → Flow Designer → New Flow
├── Trigger: HR Profile Created（或者 Schedule）
├── Action: Workday HR Spoke → Get Worker Detail
├── Condition: 根据返回值判断
└── Action: Update HR Profile（更新 HRSD 数据）
```

**第 4 步：调试**

```
All → Integration Hub → Connection & Actions → 选择 Action → Test
```

### ✅ 动手练习

**练习 1（初级）**：安装 Workday Standard Integration，配置连接，手动触发一次同步，检查导入集是否有数据。

**练习 2（中级）**：配置 Workday Webhook 让 "新员工入职" 事件自动创建 HR Profile。验证步骤：
1. 在 Workday 中创建一个测试员工
2. 等待 Webhook 触发（或手动触发）
3. 检查 ServiceNow 中是否自动生成了 HR Profile

**练习 3（高级）**：用 Flow Designer 创建一个 Flow：当 HR Profile 的部门变更时，自动发给员工一条 Teams 通知。使用 Workday HR Spoke 获取最新部门名，再用 Teams Spoke 发通知。

## 4.3 SAP SuccessFactors 集成

### 架构

```
SuccessFactors
    ├── OData API (REST) ──→ SFTP/实时
    └── 定时导出 ──→ SFTP ──→ Import Set
                ↓
          ServiceNow HRSD
            └── Staging → Transform Maps → HR Profile
```

### 前置条件

| 项目 | 要求 |
| --- | --- |
| 插件 | `sn_hr_core` + SuccessFactors Spoke |
| SuccessFactors | 需要 OData API 访问权限 |
| 账号 | SF Integration User |
| 同步方式 | 实时 OData 或 定时 SFTP |

### 配置步骤

#### 第 1 步：安装集成

```
All → Store → 搜索 "SuccessFactors HR Integration" → Install
```

#### 第 2 步：配置 OData 连接

```
All → SuccessFactors Integration → Connection
```

| 参数 | 说明 |
| --- | --- |
| API URL | `https://api.successfactors.com/odata/v2` |
| Company ID | 你的 SuccessFactors 公司 ID |
| Username | 集成用户 |
| Password | 对应密码 |

#### 第 3 步：配置对象映射

```
All → SuccessFactors Integration → Object Mapping
```

| SuccessFactors 对象 | ServiceNow 目标表 | 映射说明 |
| --- | --- | --- |
| JobProfile | `sn_hr_core_job_profile` | 岗位定义 |
| User（Worker） | `sn_hr_core_profile` | 员工基本信息 |
| Employment | `sn_hr_core_job` | 员工任职信息 |
| Position | `sn_hr_core_position` | 职位信息 |
| InboundTodos | `sn_hr_integrations_todo_inbound` | 待办事项 |

#### 第 4 步：配置定时同步

```
All → SuccessFactors Integration → Schedule Sync
```

| 对象 | 推荐频率 | 建议时间 |
| --- | --- | --- |
| JobProfile | 每日 | 凌晨 2:00 |
| Worker | 每 4 小时 | 避开高峰 |
| Employment | 每 4 小时 | 同上 |
| Position | 每日 | 凌晨 2:30 |

#### 第 5 步：手动触发测试

```
All → SuccessFactors Integration → Object Mapping → 选择对象 → Execute Now
```

检查 `sn_hr_core_profile` 表中是否有数据写入。

### ⚠️ 常见坑

- **SuccessFactors OData 限流**：SF 对 OData API 有调用频率限制（通常每分钟 100 请求）。大批量同步时需做分页，建议每批次 500 条
- **字段名大小写**：SuccessFactors OData 返回字段名是驼峰式（`firstName`），ServiceNow 目标字段是下划线式（`first_name`）。Transform Map 中注意大小写转换
- **中文字符编码**：如果员工数据包含中文，确保 SFTP 文件的编码是 UTF-8 BOM，否则导入集中中文乱码
- **增量同步标记**：SuccessFactors 不直接提供增量标记。实现方式：比较 `lastModifiedDateTime` 字段，只处理最近 N 小时内变更的数据

### ✅ 动手练习

**练习 1**：安装 SuccessFactors HR Spoke，配置 OData 连接，同步 10 个测试员工的 Profile，确认数据正确映射到 `sn_hr_core_profile`。

**练习 2**：设置定时任务每 6 小时同步一次 Employment 数据。手动修改 SF 中一个员工的部门，等待同步后验证 ServiceNow 数据已更新。

## 4.4 Oracle HCM 集成

### 架构

```
Oracle HCM Cloud
    ├── REST API (HCM Data Loader)
    └── BI Publisher 报表导出 → SFTP
                ↓
          ServiceNow HRSD
            └── Staging → Transform Maps → HR Profile
```

### Spoke 集成方式

```
All → Store → 搜索 "Oracle HCM Cloud Integration"
```

#### 配置步骤

**第 1 步：安装 Oracle HCM Spoke**

```
All → Store → "Oracle HCM Cloud Integration" → Install
```

**第 2 步：配置 REST 连接**

```
All → Oracle HCM Integration → Connection
```

| 参数 | 说明 |
| --- | --- |
| Oracle HCM 实例 URL | `https://<instance>.oraclecloud.com` |
| API Version | v2（推荐） |
| Auth | OAuth 2.0 Client Credentials |
| Client ID / Secret | 从 Oracle HCM 获取 |

**第 3 步：配置数据映射**

```
All → Oracle HCM Integration → Mapping
```

| Oracle 对象 | ServiceNow 表 | 关键字段 |
| --- | --- | --- |
| Person | `sn_hr_core_profile` | PersonNumber → EmployeeID |
| Employment | `sn_hr_core_job` | AssignmentNumber → JobID |
| Department | `sn_hr_core_department` | DepartmentName → Name |

**第 4 步：测试**

```
All → Oracle HCM Integration → Test Connection
```

### ⚠️ 常见坑

- **Oracle HCM REST API 分页**：Oracle API 默认每页 200 条。需要处理 `next` 分页链接，否则只能同步前 200 人
- **OAuth Token 过期**：Oracle 的 Access Token 有效期通常为 1 小时。确保 Flow 中有 Token 刷新逻辑
- **Person 与 Employment 分离**：Oracle HCM 把人员基本信息（Person）和工作信息（Employment）分两个 API。同步时需要先拉 Person，再拉 Employment，分两步做 Transform Map

### ✅ 动手练习

安装 Oracle HCM Spoke，配置连接，手动拉取 5 条 Person 记录，对照 Oracle HCM 源数据验证 Transform Map 的正确性。

## 4.5 Integration Hub 深度配置

### 什么是 Integration Hub

Integration Hub 是 ServiceNow 的 iPaaS（集成平台即服务），核心能力：

| 能力 | 说明 |
| --- | --- |
| Spoke 市场 | 200+ 预建连接器 |
| Flow Designer | 拖拽式编排集成逻辑 |
| 自定义连接器 | REST、SOAP、JDBC、PowerShell |
| 事件驱动 | Webhook 近实时触发 |
| 认证管理 | OAuth、Basic Auth、API Key 统一管理 |

### 配置路径

```
All → Integration Hub
├── Connections → 管理所有第三方连接
├── Spokes → 查看已安装的 Spoke
├── Actions → 测试 Spoke Action
├── Flow Designer → 编排集成流程
└── Custom Connectors → 创建自定义连接器
```

### 实操：安装和配置一个 Spoke

以 Teams Spoke 为例：

**第 1 步：安装 Spoke**

```
All → Store → 搜索 "Microsoft Teams Spoke" → Install
```

**第 2 步：创建连接**

```
All → Integration Hub → Connections → New
```

| 参数 | 值 |
| --- | --- |
| Spoke | Microsoft Teams |
| Connection Name | `teams_prod` |
| Auth Type | OAuth 2.0 |
| Tenant ID | Azure AD Tenant ID |
| Client ID | Azure App Registration ID |

**第 3 步：测试 Action**

```
All → Integration Hub → Actions → 搜索 "Send Message"
→ 选择 Send Message Action → Test
```

### 自定义连接器

当市场 Spoke 不满足需求时创建自定义连接器：

```
All → Integration Hub → Custom Connectors → New
```

| 步骤 | 操作 |
| --- | --- |
| 1. 定义连接器 | 命名 + 设置端点基础 URL |
| 2. 配置认证 | 选择认证类型（REST Basic / OAuth / API Key） |
| 3. 创建 Action | 定义请求方式、路径、参数、返回处理 |
| 4. 测试 | 用 Test 功能验证 Action 返回正确 |
| 5. 发布 | 发布后在 Flow Designer 中使用 |

### Flow Designer 集成示例

```
Flow: 员工入职自动开通 Slack 账号

Trigger: HR Profile Created
    └── Condition: Employment Type = "Full-Time"
Action 1: Slack Spoke → Invite User
    ├── Email: [HR Profile].Email
    └── Channel: #general
Action 2: Teams Spoke → Send Message
    ├── Recipient: [HR Profile].Email  
    └── Message: "欢迎加入！你的 Slack 账号已开通。"
```

### ⚠️ 常见坑

- **Connection 权限**：Spoke Action 执行需要连接有对应权限（读/写）。创建 Connection 后务必用 Test 功能验证
- **Integration Hub 订阅**：Integration Hub 是按 Transaction 计费的。每个 Action 调用消耗 1 个 Transaction。大量同步场景注意预算
- **Action 超时**：默认 Action 超时 30 秒。大批量数据操作容易超时。建议拆分为批量 + 异步处理
- **错误重试**：默认没有自动重试。网络抖动时 Action 会失败。建议在 Flow 中加入 Retry 逻辑（圈出 Action 块 → 配置 Retry）

### ✅ 动手练习

**练习 1**：安装 Slack Spoke，配置连接，创建一个 Flow 当 HR Profile 创建时自动在 Slack 的 `#hr-announcements` 频道发一条欢迎消息。

**练习 2**：创建一个自定义 REST 连接器，连接一个外部天气 API（如 `https://api.openweathermap.org`），创建一个 Action `Get Weather`，在 Flow Designer 中调用它。

**练习 3**：调试一个 Spoke Action 失败。检查 Connection → Test，检查 Action 参数，检查 `syslog` 中的错误信息。

## 4.6 HR Multi-Instance Integration (HR MII)

### 适用场景

跨国企业，每个国家/地区有独立 ServiceNow 实例，需要：

- 统一管理全球 HR 服务
- 跨实例同步案例、知识、服务目录
- 总部实例作为 Hub，分支实例作为 Spoke

### 架构

```
总部实例 (Hub)
├── HR MII 主配置
├── 全局知识库
├── 全球案例监控
└── 统一服务目录
    ↓ https/mTLS
┌────────┬────────┬────────┐
│ 中国    │ 美国    │ 欧洲    │
│ 实例    │ 实例    │ 实例    │
└────────┴────────┴────────┘
```

### 配置步骤

**第 1 步：激活插件**

每个实例都需要激活：

```
All → System Applications → Plugins → 搜索 "HR Multi-Instance Integration"
```

插件 ID：`sn_hr_mii`

**第 2 步：配置 Hub 实例**

```
All → HR MII → Global Settings
├── 设置 Hub 实例 URL
├── 配置认证（mTLS 或 Basic Auth）
└── 定义共享内容策略
```

**第 3 步：配置 Spoke 实例**

```
All → HR MII → Instance Configuration
├── 注册到 Hub 实例
├── 配置同步内容（案例/知识/目录）
└── 设置同步频率
```

### ⚠️ 常见坑

- **网络策略**：分支实例需要能直接访问总部实例 API。企业网络策略常阻止实例间直接通信。提前和网络团队确认
- **数据冲突**：同一知识文章在两边都修改 → 以 Hub 版本为准。版本冲突时 Hub 覆盖 Spoke
- **合规要求**：有些国家要求数据不出境（如中国、欧盟）。HR MII 支持过滤：仅同步脱敏数据，或不同步某些字段

### ⚠️ 常见坑

- **Screen Pop 延迟**：来电弹屏依赖 Caller ID 匹配客户记录。如果来电号码在 ServiceNow 中没找到，弹屏会延迟或失败。建议配置 "号码模糊匹配"（去掉国家码前缀）
- **CTI 适配器冲突**：如果同时有多个 CTI 适配器（Genesys + 另一个电话系统），Agent Workspace 可能出现混乱。生产环境只配一个
- **Twilio 区域**：国内用户选 `cn.twilio.com` 区域，否则通话延迟大

### Slack 集成

#### Spoke 方式

```
All → Store → 搜索 "Slack Spoke" → Install
```

#### 配置 OAuth

```
All → Integration Hub → Connections → New → Slack
├── Client ID: Slack App Credentials
├── Client Secret: 对应密钥
└── Scopes: chat:write, channels:manage, users:read
```

#### 可用 Action

| Action | 用途 |
| --- | --- |
| Post Message | 发消息到频道或用户 |
| Invite User | 邀请用户加入频道 |
| Create Channel | 创建 Slack 频道 |

### 常用自动化场景

| 场景 | Trigger | Action |
| --- | --- | --- |
| 新员工入职 | HR Profile Created | Teams Spoke 发欢迎消息 + Slack Spoke 邀请入频道 |
| 案例分配 | Case Assigned | Teams Spoke 提醒 HR 处理 |
| 知识更新 | KB Article Published | Slack Spoke 通知 HR 团队 |
| 休假审批 | Time Off Request Approved | Teams Spoke 自适应卡片显示审批状态 |

### ⚠️ 常见坑

- **Teams 消息限制**：Teams API 单条消息上限 28KB。超过会静默截断。长内容分多条发送
- **Slack Token 生命周期**：Slack Bot Token 不自动过期，但如果重新安装 App 会生成新 Token。记得更新 Connection
- **OAuth 重定向**：配置 OAuth 时 Redirect URI 必须填 `https://<你的实例名>.service-now.com/oauth_redirect.do`，填错会导致认证失败
