### 1.2 认证流程

DocuSign JWT OAuth 流程：
1. 使用 RSA 私钥生成 JWT assertion（包含 Integration Key、User ID、scopes）
2. 用 assertion 换取 access token（1小时有效期）
3. 在 API 请求中携带 Bearer token
4. Token 自动缓存到 `access_token.json`，过期自动刷新

**学习要点**：JWT 认证是服务器到服务器的通信方式，无需用户交互。Demo 环境使用 `account-d.docusign.com` 作为 OAuth 端点。

## 二、模板设置（Template Configuration）

### 2.1 模板概念

DocuSign 模板是预配置的文档集合，包含：
- **文档（Documents）**：一个或多个 PDF/Word 文件
- **签收人角色（Recipient Roles）**：谁需要签署（Employee、HR、Manager 等）
- **表单字段（Tabs）**：需要填写的空白位置（文本框、日期、复选框等）

### 2.2 创建模板的方式

| 方式 | 适用场景 | 工具 |
|------|----------|------|
| Web UI | 手动创建，适合简单场景 | apps-d.docusign.com |
| REST API | 程序化创建，适合批量 | POST /templates + PUT /documents |

### 2.3 模板数据结构

```
Template
├── name: 模板名称
├── documents[]           # 文档列表
│   ├── documentId: 1
│   ├── name: "Offer Letter.pdf"
│   └── fileExtension: "pdf"
├── recipients.signers[]  # 签署角色
│   ├── roleName: "Employee"
│   ├── recipientId: "1"
│   └── tabs: {}          # 表单字段
└── status: "created"
```

### 2.4 表单字段类型（Tab Types）

| 类型 | API 名称 | 适用场景 |
|------|----------|----------|
| 文本框 | textTabs | 姓名、地址、电话号码 |
| 日期框 | dateTabs | 入职日期、合同到期日 |
| 数字框 | numberTabs | 薪资、工作时长 |
| 复选框 | checkboxTabs | 同意条款、选择项 |
| 下拉列表 | listTabs | 性别、部门选择 |
| 单选按钮 | radioGroupTabs | 二选一选项 |
| 邮箱 | emailTabs | 电子邮箱 |
| 电话 | phoneTabs | 手机号码 |
| 附件 | attachmentTabs | 上传身份证照片、银行卡照片 |

### 2.5 标签定位方式

| 方式 | 说明 | 推荐度 |
|------|------|--------|
| Anchor String | 文档中标记文字定位 | ⭐⭐⭐ 推荐 |
| 绝对坐标 (x, y) | 页面像素坐标 | ⭐⭐ 需调试 |
| 相对位置 | 相对于锚点的偏移 | ⭐⭐ |

Anchor String 是最可靠的方式：在 Word/PDF 文档中插入标记文字（如 `{{employee_name}}`），DocuSign 会根据该文字位置自动放置表单字段。

### 2.6 多文档模板

一个模板可以包含多个文档，每个文档有各自的表单字段。最适合入职场景——将合同、NDA、授权书等放在同一个模板中，一封邮件发送所有文件。

```
Template "入职套装"
├── Document 1: 录用通知书.pdf
│   └── Tabs: employee_name, position, salary
├── Document 2: 保密协议.pdf
│   └── Tabs: employee_name, nda_company, nda_date
└── Document 3: 个人信息授权书.pdf
    └── Tabs: employee_name, id_card, consent_date
```

## 三、API 关键流程

### 3.1 从模板创建信封

```
POST /v2.1/accounts/{accountId}/envelopes
{
  "templateId": "guid",
  "templateRoles": [{
    "roleName": "Employee",
    "name": "张三",
    "email": "289631530@qq.com",
    "tabs": {
      "textTabs": [
        {"tabLabel": "position", "value": "装配工"},
        {"tabLabel": "salary", "value": "3500"}
      ]
    }
  }],
  "emailSubject": "请签署: 录用通知书",
  "status": "sent"
}
```

### 3.2 批量发送（Bulk Send）

3-step API 流程：
1. `POST /bulk_envelope_lists` — 创建批量列表（含所有收件人）
2. `POST /envelopes/bulk_send` — 将列表链接到模板
3. `GET /bulk_envelope_lists/{listId}` — 检查状态

**注意**：Demo 环境可能不支持 Bulk Send API（返回 404），需降级为逐个发送。

### 3.3 表单数据提取

三种方法按优先级尝试：
1. `GET /envelopes/{id}/form_data` — 最直接，返回 `{name, value}` 对
2. `GET /envelopes/{id}/recipients/{rid}/tabs` — 遍历所有标签类型
3. `GET /envelopes/{id}/custom_fields` — 自定义字段（以 `cf__` 前缀）

### 3.4 文档下载

```
GET /v2.1/accounts/{accountId}/envelopes/{envelopeId}/documents/{documentId}
```

- `documentId = "combined"` 下载合并 PDF（所有文档在一个文件中）
- 其他 documentId 下载单个文档

### 4.3 表单数据管道

Tab 值（表单字段）传递流程：

```
XLSX 数据 → generate_template_csv() → CSV (列名=tabLabel)
                                  → send_onboarding_envelopes()
                                  → POST /envelopes (tabs 传参)
                                  → GET /envelopes/{id}/form_data (验证)
```

**关键发现**：
- `PUT /templates/{id}/recipients` 返回 200 **但不添加** 表单字段 —— 必须用 `POST /templates/{id}/recipients/{rid}/tabs`
- CSV 列名必须与模板中的 `tabLabel` 完全一致，否则字段为空
- `employee_name` 同时作为收件人姓名和表单字段，需在 tabs 中额外传入

## 五、风险与建议

### 5.1 已知限制

1. **Bulk Send API**: Demo 账户返回 404，已实现自动降级为逐个发送。生产环境应支持 Bulk API
2. **模板创建**: 需要在 Web UI 或通过 API 上传实际文档文件
3. **Tag 位置**: 当前使用绝对坐标 (x,y)，生产环境应改用 Anchor String
4. **datetime.utcnow()**: 在 Python 3.12+ 已弃用，需迁移到 `datetime.now(datetime.UTC)`

### 5.2 生产环境建议

1. 切换到正式 DocuSign 账户（非 Demo）
2. 使用 Anchor Strings 替代绝对坐标定位表单字段
3. 配置 Connect Webhook 自动追踪信封状态变化
4. 设置 HMAC 密钥验证 Webhook 签名
5. 使用 OAuth Consent 流程（而非 JWT）让最终用户授权
