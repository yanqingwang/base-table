## 四、小程序真机全链路（发卡→兑换→消费→对账）

1. 确认/修正 `code/card-counter-miniapp/utils/config.js` 的 service 指向（现为 flask-z9hh，与生产小程序后端一致 ✓）
2. 发卡：商户端网页或 `POST /api/issuer/batches`（员工 JWT）生成批次，取明文卡密（仅此一次）
3. 兑换：小程序「卡包 → 卡密兑换」输入卡密 → 成功弹层显示卡号/面额/余额；重复输入同码应报"已被兑换"
4. 消费：核销侧消费后，卡包余额同步减少
5. 对账：`curl -H "X-Platform-Token: <TOKEN>" -X POST $BASE/api/platform/recon/run` → 差异单 0、准确率 1.0

### ⚠️ 架构注意事项（两本账）
- flask 移植版与 commercial 的卡密表**同名不同列**（snake_case vs camelCase），两服务绝不能指向同一 MySQL 库。现状：flask-z9hh 用 MySQL `card_counter`（小程序真账本）；cardcount-web 用容器临时 SQLite（网页演示账本，实例回收即清空）。
- 网页版要和小程序共用统一账本，需把 commercial 的双端 UI 并入 flask 后端（后续任务），或给 cardcount-web 单独建一个 MySQL 库（仍与小程序不通账）。
