## 一、部署前检查

1. **代码**：改动已提交并 push 到对应仓库 main
   - 商业版后端/控制台 → `github.com/yanqingwang/card-counter-flask`
   - Demo 网页 → `github.com/yanqingwang/card-counter-commercial`
2. **本地测试全绿**（见测试手册第一节）
3. **兼容性红线**：生产容器为 `python:3.11-slim`——不得使用 3.12+ 语法（典型坑：f-string 嵌套同类引号，PEP 701）。提交前可在 venv（3.11）里 `python -m py_compile <改动文件>` 预检
4. **数据安全自评**：本次改动是否只增不改？
   - 新增表：无需迁移，`db.create_all()` 启动自动建
   - 既有表加列：`__init__.py` 轻量迁移补列（MySQL information_schema / SQLite PRAGMA 双路径，**必须两条路径都写**）
   - 改列/删列/改语义：禁止直接上线，需专项迁移方案

## 三、发布流程

### 常规（推荐）：push 即发布

```bash
cd /home/wang/wk/code/card-counter-flask      # 或 card-counter-commercial
git push origin main                           # 流水线自动构建 + 全量发布，约 5~30 分钟
```

进度：控制台 → 服务 → 部署发布（显示"部署中/当前步骤：执行流水线"）。
构建完成历史版本自动接管流量，服务页「线上版本」更新即成功。

### 备用：控制台手动发布

服务 → 部署发布 → 发布 → 选择方式 **执行流水线**（绑定仓库）→ 发布。
⚠️ 不要选「绑定 GitHub 仓库」模式（表单可能残留其他项目的仓库/分支）。

### 版本回退

服务 → 部署发布 → 回退（选择历史版本）。回退不改数据库结构；若新版本已建新表，回退无影响（旧代码不读新表）。

## 四、部署后验证

### 1. 部署本身是否成功

- 服务页「线上版本」版本号 +1 且备注为新 commit message；实例数量 ≥1
- 操作记录页出现「部署完成，流量类型：全量发布」；出现「服务部署失败」红条则看失败日志（最近案例：`SyntaxError: f-string unmatched '('`）

### 2. flask-z9hh（公网未开放 → 控制台云端调试）

| 调试请求 | 预期 |
|---|---|
| GET `/api/health` | 200 `{"status":"ok"}` |
| GET `/api/platform/recon` + `X-Platform-Token: <令牌>` | 200 `{"code":0,...}` |
| 同上无令牌 | 403 `平台令牌缺失或无效` |
| POST `/api/redeem` 无登录态 | 401 |

小程序真机：登录 → 卡包 → 卡密兑换 → 输入明文码 → 成功弹层；重复兑换报"已被兑换"。

### 3. cardcount-web（公网直接 curl）

```bash
B=https://cardcount-web-281177-5-1453124923.sh.run.tcloudbase.com
TOK=<平台令牌>
curl -s $B/api/health                                   # {"status":"ok"}

```

## 五、已知坑与纪律

1. **gunicorn/语法坑**：f-string 嵌套同类引号在 py3.11 是 SyntaxError；曾导致 commercial `-005` 起所有版本静默不上线（线上停在旧版一周）。任何部署后必须按第四节验证，**不能只看流水线变绿**
2. **流水线串行**：上一次流水线未结束时再次发布会报 `ResourceInUse`（流水线运行中）——等空闲再发
3. **服务设置保存 ≠ 新代码**：修改环境变量触发的重发沿用**当前线上版本代码**；要上新代码必须 push（或手动执行流水线）
4. **两库隔离**：cardcount-web 的 `DB_URL` 永远不许指向 `card_counter` MySQL
5. **密钥纪律**：令牌/密码只存控制台与仓库外 `/home/wang/wk/.secrets/`（已 gitignore），不入 git
6. **回退后建表**：新版本建的表回退后仍在库中（create_all 幂等），重新发布不会重复建
