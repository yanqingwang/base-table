## 3.1 知识管理架构

```
三层体系：
┌─────────────────────────────────────────┐
│  Employee Center / Portal               │  ← 员工搜索和提问的界面
├─────────────────────────────────────────┤
│  AI Search (RAG 引擎)                    │  ← 检索知识 + LLM 生成答案
│  ├── 关键词搜索 (BM25)                   │
│  └── 语义搜索 (Embedding)                │
├─────────────────────────────────────────┤
│  知识库 (Knowledge Base)                 │  ← 内容存储
│  ├── KB Articles (知识文章)              │
│  ├── Knowledge Blocks (知识块)           │
│  ├── Attachments (附件: PDF/DOC/PPT)    │
│  └── Service Catalog (服务目录)          │
└─────────────────────────────────────────┘
```

**核心原则**: AI Search 不是搜索整个企业内容 — 它只搜索你明确告诉它去检索的数据源。

## 3.2 实战：创建知识库

### Step 1 — 创建 HR 知识库

```
HR Administration → Knowledge Management → Create New Article
```

第一次访问时，系统会提示创建知识库：

```
Knowledge → Knowledge Bases → New
```

| 字段 | 填写示例 | 说明 |
|------|---------|------|
| **Name** | "HR Knowledge Base" | 知识库名称 |
| **ID** | hr_knowledge | 系统 ID |
| **Description** | "HR 政策和流程知识库" | 用途说明 |
| **Owner** | HR Knowledge Manager | 所有者 |
| **Enable Topic Publishing** | ✅ 勾选 | 允许按主题发布 |

### Step 2 — 创建第一篇文章

```
HR Administration → Knowledge Management → Create New Article
```

**文章结构**:
| 元素 | 说明 | AI 关联 |
|------|------|---------|
| **标题** | 清晰描述问题 | AI 匹配搜索关键词 |
| **富文本正文** | 完整解决方案 | LLM 生成答案的依据 |
| **摘要** | 简短的概述 | AI 展示在搜索结果中 |
| **Topic** | 主题分类 | 搜索过滤 |
| **Keywords** | 关键词标签 | 增强检索匹配 |
| **User Criteria** | 可见性控制 | 权限过滤 |
| **Approved for Now Assist** | AI 可见性标记 | ⭐ AI 核心开关 |

> ✏️ **练习**: 创建一篇知识文章，主题为 "如何申请年假"，包含：
> - 标题: "年假申请流程"
> - 正文: 分步骤说明（Step 1: 登录 Portal → Step 2: 选择 "Leave Request" → ...）
> - 关键词: 年假, PTO, vacation, leave
> - User Criteria: All Employees

### Step 3 — 配置 User Criteria（可见性控制）

User Criteria 控制**哪些员工能看到哪些文章**。

```
Knowledge → User Criteria → New
```

**常用 User Criteria 示例**:
| 名称 | 条件 | 用途 |
|------|------|------|
| All Employees | 始终为真 | 通用政策 |
| US Employees | Location 包含 US | 美国本地政策 |
| HR Only | Role 包含 sn_hr_core.user | HR 内部文档 |
| Managers Only | Role 包含 sn_hr_core.manager | 管理者指南 |

**关联到知识文章**:
```
打开文章 → User Criteria 字段 → 选择 "US Employees"
   → 只有 US 员工能看到这篇文章
```

> ⚠️ **关键提醒**: User Criteria 与 AI Search 的权限是统一的 — AI 只会返回员工有权限查看的内容。

## 3.3 进阶功能：知识块（Knowledge Blocks）

### 为什么需要知识块？

传统知识文章是 **整篇索引** 的，AI 检索时可能返回整篇文章。知识块允许你将文章**拆分为可重用的片段**，AI 可以精确检索到最相关的片段。

### 创建知识块

```
Knowledge → Knowledge Blocks → New
```

| 字段 | 说明 |
|------|------|
| **Name** | 块的名称 |
| **Content** | 块的内容（可引用到多篇文章） |
| **Topics** | 关联主题 |
| **Owner** | 所有者 |

### 在文章中嵌入知识块

```
编辑知识文章 → 插入 Knowledge Block
   → 选择已创建的知识块
   → 保存
```

> 💡 **何时使用**: 
> - 跨多篇文章引用的政策文本（如 "加班政策"）
> - 经常更新的流程说明（如 "报销限额"）
> - 法律/合规要求的统一表述

## 3.4 实战：AI Search 配置

### 数据源配置

```
All → AI Search → Administration → Search Data Sources
```

**关键配置项**:

| 配置 | 路径 | 说明 |
|------|------|------|
| **Knowledge Base** | AI Search → Data Sources → KB | 选择索引哪些知识库 |
| **Attachment Search** | AI Search → Data Sources → Attachments | 选择索引 PDF/DOC/PPT 等 |
| **External Content** | AI Search → External Content Connectors | SharePoint / Confluence |
| **Service Catalog** | AI Search → Data Sources → Catalog | 服务目录项索引 |

### 编码查询字符串（Encoded Query）

编码查询字符串是 AI Search 的 **预过滤器**，在将内容发送给 LLM 之前过滤。

**配置路径**:
```
AI Search → Data Sources → 选择 KB → Source Criteria Tab
   → Encoded Query 字段
```

**示例**:
```
topic=hr_policy^ORtopic=benefits^ORtopic=payroll
```

**作用**: 只有符合编码查询条件的文章才会被 LLM 使用。

> ⚠️ **常见错误**: 编码查询字符串过于严格 → AI 什么也找不到。过于宽松 → AI 可能返回不相关内容。

### "Approved for Now Assist" 标记

这是 AI 内容的**最终控制开关**。只有标记为 "Approved" 的文章才会被 AI 使用。

**配置**:
```
打开知识文章 → 勾选 "Approved for Now Assist" 字段 → 保存
```

**推荐策略**:
```
Phase 1: 选择 10-20 篇高质量文章 → 标记 Approved → 测试 AI 效果
Phase 2: 根据测试反馈，逐步扩大 Approved 范围
Phase 3: 建立治理流程，新文章必须先 Approved 才能被 AI 使用
```

> ⚠️ **关键警告**: "If you skip content audit and just mark everything Approved, you WILL get bad AI responses. Bad AI → employees don't trust → project fails. Content quality is the foundation."

### Result Improvement Rules（RIR）

RIR 用于提升特定文章的搜索排名。

**配置路径**:
```
AI Search → Administration → Result Improvement Rules → New
```

**示例配置**:
| 规则名称 | 条件 | 提升效果 |
|---------|------|---------|
| "热门问题" | 关键词包含 [年假, 病假, 报销] | 排名提升 2x |
| "高管相关" | KB = Executive Policies | 排名提升 3x |
| "紧急政策" | 关键词包含 [合规, 截止日期] | 排名提升 1.5x |

## 3.5 内容治理最佳实践

### 启动前的内容审计流程

```
Step 1: 导出所有现有知识文章
Step 2: 评估每篇文章
    ├── 是否过时？→ 标记删除或更新
    ├── 是否有重复？→ 合并
    ├── 格式是否正确？→ 统一富文本标准
    └── 是否有元数据？→ 补充 topic/audience/keywords
Step 3: 分配所有者
    └── 每篇文章需要明确的 owner 和 reviewer
Step 4: 标记控制
    └── 仅高质量文章勾选 "Approved for Now Assist"
Step 5: 建立刷新周期
    └── 季度审查 vs 半年审查
```

### 治理角色定义

| 角色 | 职责 | 需要角色 |
|------|------|---------|
| **Content Owner** | 文章创建和更新 | knowledge_author |
| **Content Reviewer** | 质量审核和发布 | knowledge_publisher |
| **KB Admin** | 知识库整体管理 | knowledge_admin |
| **AI Content Manager** | Approved for Now Assist 控制 | hr_admin + knowledge_admin |

### 监控指标

```
AI Search Analytics → Dashboard
├── 采纳率 (Adoption Rate) → 目标 > 60%
├── 缺陷率 (Defect Rate) → 目标 < 5%
├── Top 搜索词 → 指导内容优化
└── Zero Result 查询 → 内容缺口
```

## 3.6 外部内容连接器

### SharePoint Online 连接

```
AI Search → External Content Connectors → SharePoint Online → Configure
```

**配置项**:
| 字段 | 说明 |
|------|------|
| SharePoint Site URL | SharePoint 站点地址 |
| Authentication | OAuth 2.0 配置 |
| Sync Frequency | 同步频率（建议每日） |
| Crawl Scope | 爬取范围（站点/库/文件夹） |

### Confluence Cloud 连接

```
AI Search → External Content Connectors → Confluence Cloud → Configure
```

> 💡 **最佳实践**: 外部内容连接器配置后，需要 **24-48 小时**才能完成首次索引。

## 3.7 常见坑与避坑

| 坑 | 症状 | 解决方案 |
|----|------|----------|
| 内容未审计 | AI 返回过时/错误信息 | 启动前强制执行内容审计 |
| 编码查询太严格 | AI 搜索无结果 | 放宽条件，逐步缩小 |
| 忘记勾选 Approved | AI 返回空 | 检查知识文章标记 |
| 用户标准未配置 | 员工看到不该看到的内容 | 配置 User Criteria + ACL |
| 附件未索引 | PDF 中的内容搜不到 | 确认 Attachment Search 已启用 |
| 外部内容同步延迟 | SharePoint 新内容搜不到 | 检查同步频率配置 |

## ✅ 动手练习

### 练习 1：知识库搭建
1. 创建一个 "HR Knowledge Base"
2. 创建 3 篇知识文章（年假、病假、报销）

### 练习 2：AI Search 配置
1. 打开 AI Search Administration
2. 确认 HR Knowledge Base 已作为数据源
3. 配置编码查询字符串，只检索你创建的那 3 篇文章
4. 为 2 篇文章标记 "Approved for Now Assist"

### 练习 3：搜索测试
1. 在 Employee Center 中搜索 "如何申请年假"
2. 观察搜索结果
3. 如果 Genius Result Card 未出现，排查配置问题
4. 配置一条 Result Improvement Rule，提升年假文章的排名

### 练习 4：内容审计模拟
假设你的组织有 500 篇 HR 知识文章。设计一个内容审计计划：
1. 审计流程是什么？
2. 谁负责审计？
3. 多长时间审计一次？
4. 如何标记哪些文章适合 AI？
