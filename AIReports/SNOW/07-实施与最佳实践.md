## 7.1 部署准备

### 插件依赖与版本检查

| 插件 | 插件 ID | 最低版本要求 | 用途 |
|------|---------|-------------|------|
| HRSD Core | `com.sn_hr_core` | Zurich | HRSD 基础功能 |
| Generative AI Framework | `com.sn_gaf_hr` | 11.2+ | AI 基础设施 |
| AI Search | `com.sn_ai_search` | Zurich | RAG 检索 |
| Now Assist for HRSD | `com.sn_hr_now_assist` | 最新 Store 版本 | 生成式 AI 能力 |
| AI Agent Studio | `com.sn_ai_agent_studio` | Zurich | Agent 创建 |
| Predictive Intelligence | `com.sn_predictive_intelligence` | — | 预测功能（可选） |
| Integration Hub | `com.sn_integration_hub` | — | 第三方集成（可选） |

**检查路径**:
```
All → System Definition → Plugins → 搜索每个插件 ID
   → 确认版本号 ≥ 最低要求
   → 确认状态为 "Active"
```

> ⚠️ **关键提醒**: GenAI Controller (GAF) 必须先于其他 AI 插件激活。如果版本低于 11.2，Now Assist 技能将不可用。

### 环境就绪检查清单

```
□ 版本兼容性 — 检查 Release Notes 中已知问题
   路径: ServiceNow Docs → Release Notes → HRSD
□ 自定义影响评估 — 检查自定义字段/表单是否会干扰 AI
   工具: Now Assist Admin → Readiness Check
□ 许可证确认 — Now Assist Assist 配额是否充足
   路径: Now Assist Admin → Dashboard → Usage
□ 沙盒环境 — 是否同步了生产数据用于测试
□ 升级窗口 — 是否分配了升级维护时间
□ 用户培训 — 是否安排了 HR 代理的 AI 功能培训
```

## 7.2 知识准备（Go-Live 前必做）

### 5 步内容审计法

**Step 1: 导出与盘点**
```
Knowledge → Reports → 导出所有文章 CSV
    → 统计总数，按 KB/COE/Topic 分类
    → 识别无所有者的文章
```

**Step 2: 质量评估（逐篇过）**
| 评估项 | 标准 | 操作 |
|--------|------|------|
| 内容是否过时？ | 创建日期 < 1 年 | 过时 → 标记删除或更新 |
| 是否有重复？ | 同主题文章 > 1 篇 | 合并为 1 篇 |
| 格式是否统一？ | 是否有表格/图片/排版混乱 | 统一富文本标准 |
| 元数据是否完整？ | Topic/Keywords/Summary 是否填写 | 补充缺失字段 |

**Step 3: 所有权分配**
```
每篇文章必须有:
□ Owner（负责更新）
□ Reviewer（负责审核质量）
□ Review Date（下次审查日期）
```

**Step 4: AI 标记控制**
```
对每篇高质量文章:
□ 勾选 "Approved for Now Assist" ← 只勾选经过评估的
□ 配置编码查询字符串 ← 按 COE/部门过滤
```

**Step 5: 建立治理机制**
```
□ 刷新周期: 季度审查 vs 半年审查
□ 监控指标: 采纳率目标 > 60%，缺陷率目标 < 5%
□ 反馈闭环: "有帮助/无帮助" 评价 → 触发内容优化
```

> ⚠️ **关键警告**: "If you skip content audit and just mark everything Approved, you WILL get bad AI responses. Bad AI → employees don't trust → project fails. Content quality is the foundation."

## 7.3 Agent 部署

### 3 阶段部署流程

```
┌─────────────────────────────────────────────┐
│  阶段 1: DEV（开发实例）                       │
│  ├── 安装所有依赖插件                          │
│  ├── 创建和配置 Agent                          │
│  ├── 使用**真实案例数据**测试                    │
│  │   ├── 测试 Case Summarization 质量          │
│  │   ├── 测试 Agentic Workflow 全流程           │
│  │   ├── 测试 RAG 检索准确度                    │
│  │   └── 测试 Human-in-the-Loop 交互            │
│  ├── 记录问题和调整                             │
│  └── 导出 Update Set                           │
├─────────────────────────────────────────────┤
│  阶段 2: UAT（测试实例）                        │
│  ├── 导入 Update Set                           │
│  ├── HR 团队试用验证                            │
│  ├── 收集反馈 → 迭代调整                       │
│  └── 用户验收签字                              │
├─────────────────────────────────────────────┤
│  阶段 3: PROD（生产实例）                       │
│  ├── 通过 Change Request 导入 Update Set       │
│  ├── 小范围试点 → 先给 HR 团队使用              │
│  ├── 监控 Assist 用量和质量                     │
│  ├── 扩大范围 → 全体员工可用                    │
│  └── 持续优化循环                              │
└─────────────────────────────────────────────┘
```

### Human-in-the-Loop 级别设计

| 自动化级别 | 描述 | 适用场景 | AI 角色 | 人工角色 |
|-----------|------|---------|---------|---------|
| L1 — 完全自动 | AI 独立处理，无需人工 | 非关键查询、知识推荐 | 处理 → 关闭 | 仅监控 |
| L2 — 建议模式 | AI 推荐 → 人工确认 | 案例摘要、解决建议 | 生成建议 | 审批发布 |
| L3 — 人机协作 | 多轮交互 | 复杂案例处理 | 提供方案 | 细化执行 |
| L4 — 专家模式 | 人工主导，AI 辅助 | 敏感案例、法律相关 | 辅助检索 | 主导处理 |

**推荐启动策略**: 从 L1/L2 开始，积累信心后逐步扩大到 L3。

## 7.4 集成策略

### 模式决策树（实操版）

```
问题：这个集成场景是什么？
    ↓
是 HR 主系统的员工数据同步吗？
    ├── 是 → 使用 Spoke 或 Store 标准集成
    │    ├── Workday → Workday HR Spoke
    │    ├── SuccessFactors → SF Spoke
    │    └── Oracle HCM → Oracle Spoke
    └── 否 → ↓
是实时服务交互需求吗？
    ├── 是 → Integration Hub + Webhook
    │    ├── 员工信息变更 → Webhook 近实时同步
    │    └── 审批流程 → Flow Designer + REST API
    └── 否 → ↓
是 AI Agent 间协作吗？
    ├── 是 → MCP/A2A (AI Agent Fabric)
    └── 否 → ↓
        自定义 REST/SOAP API 集成
        (最后手段，考虑维护成本)
```

### 4 条核心原则

| 原则 | 说明 | 违背的后果 |
|------|------|-----------|
| HCM 为事实源 | 人员数据只从 HCM 来，不在 SNOW 中创建 | 数据不一致 |
| STP 直通处理 | 能自动化的不要人工干预 | 效率降低 |
| Webhook 事件驱动 | 近实时同步优于批量定时同步 | 数据延迟 |
| 权限一致 | HCM 与 HRSD 权限对齐 | 越权访问 |

## 7.5 治理模型

### AI 角色与职责矩阵

| 角色 | 负责人 | 职责 | 访问权限 |
|------|--------|------|---------|
| AI 管理员 | IT/Platform Team | 配置管理、许可证管理、监控 | `sn_nowassist_admin` |
| 知识管理者 | HR Content Team | 知识库质量、内容审计 | `knowledge_admin` |
| HR 业务所有者 | HR BP | 用例定义、验收标准 | `sn_hr_core.admin` |
| AI 治理官 | Compliance | 合规审查、风险评估 | `sn_aict.admin` |
| IT 支持 | Service Desk | 故障处理、升级管理 | `sn_hr_core.agent` |

### 合规框架速查

| 框架 | 适用地区 | 关键要求 | AI Control Tower 内置支持 |
|------|---------|---------|--------------------------|
| **EU AI Act** | 欧盟 | 高风险 AI 系统可审计性 | ✅ Risk Assessment dashboard |
| **NIST AI RMF** | 美国/全球 | 映射→衡量→管理→治理 | ✅ AI RMF framework 模板 |
| **GDPR** | 欧盟 | 数据保护影响评估 | 🔶 需额外配置 |

### 审查周期建议

| 频率 | 内容 | 负责人 |
|------|------|--------|
| **每周** | AI Assist 使用量和质量仪表板 | AI 管理员 |
| **每月** | Agent 性能评估、知识库更新 | 知识管理者 |
| **每季度** | AI 治理回顾、合规检查 | AI 治理官 |
| **每年** | AI 策略评估、许可证续期 | AI 管理员 + 业务所有者 |

## 7.6 持续优化

### 关键指标看板

| 指标 | 计算方式 | 目标值 | 不及格时的行动 |
|------|---------|-------|--------------|
| AI 采纳率 | AI 建议被人工采纳的比例 | > 60% | 检查 AI 质量，调整提示词 |
| AI 缺陷率 | AI 输出被人工修改/拒绝的比例 | < 5% | 内容审计，模型切换 |
| 员工自助解决率 | 不联系人工代理的比例 | > 40% | 丰富知识库，改善搜索 |
| 案例解决时间 | 平均时长 | 持续下降 | 检查工作流瓶颈 |
| 员工满意度 | CSAT 评分 | > 4.0/5.0 | 调研痛点，迭代优化 |

### 优化闭环

```
收集指标 → 识别偏差 → 分析根因 → 制定方案 → 实施调整 → 验证效果 → 回到收集
```

## 7.7 常见坑与避坑

| 坑 | 风险等级 | 表现 | 避坑策略 |
|----|---------|------|----------|
| 修改核心 HR 表字段 | 🔴 致命 | AI 功能不工作、升级失败 | 配置优先，绝不自定义核心字段 |
| 知识库未审计直接启用 AI | 🔴 致命 | AI 答非所问 → 员工不信任 | 启动前强制执行内容审计 |
| 集成模式选择错误 | 🟡 高 | 数据不同步、维护成本高 | 用决策树评估 |
| 忽略版本升级影响 | 🟡 高 | 自定义功能在升级后失效 | Update Set 管变更，读 Release Notes |
| AI Agent 期望过高 | 🟡 高 | 业务方失望 → 项目被质疑 | 小范围试点，设预期管理 |
| 变更管理不足 | 🟡 高 | 员工抵制 → 低采纳率 | OCM 计划，分阶段推出 |
| 权限配置不当 | 🟡 中 | 数据泄露或员工看不到内容 | 提前规划 ACL 策略 |
| 只关注桌面端 | 🟢 低 | 移动端体验差 | 确保 Portal 和 VA 的移动端适配 |
| 跳过 Readiness Check | 🟡 高 | 部署后才发现兼容性问题 | 使用诊断工具提前发现 |
| 未配置 Fulfillment Instructions | 🟡 中 | Case Planner Agent 无法生成计划 | 为每个 HR Service 配置指导文件 |

## ✅ 动手练习

假设你的组织有 500 篇 HR 知识文章：
1. 设计一个 4 周的审计计划（每周做什么）
2. 创建审计评估表模板
3. 确定哪些文章标记 Approved for Now Assist 的标准

### 练习 3：治理设计
为一家 5000 人跨国企业设计 AI 治理框架：
1. 定义各角色和职责
2. 设计合规检查流程
3. 编写审查日历

### 练习 4：避坑案例
分析以下场景：一家公司部署 Now Assist 后，HR 代理发现 AI 生成的案例摘要经常遗漏关键信息。问题出在哪里？如何解决？
