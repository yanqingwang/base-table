```
如果尚未购买 → 联系 ServiceNow 客户团队确认许可
如果已购买 → 确认许可证已在实例上生效
```

### 插件依赖

```
GenAI 相关插件:
├── Generative AI Controller (版本 ≥ 11.2) ← 核心引擎
│   └── 依赖: Now Platform Base
├── Now Assist for HRSD (最新 Store 版本)
│   └── 依赖: HRSD Core, GenAI Controller, AI Search
├── AI Search

    └── 依赖: Now Platform Base

**安装操作**:
```
All → System Definition → Plugins
   → 按顺序激活：
   1. Generative AI Controller (com.sn_generative_ai_controller)
   2. AI Search (com.sn_ai_search)
   3. Generative AI Framework - HRSD (com.sn_gaf_hr)

```

> ⚠️ **关键提醒**: 每个插件激活需要 5-15 分钟。按顺序激活！GenAI Controller 必须先于其他所有 AI 插件。如果同时激活，可能会因依赖未满足而报错。

```

## 2.2 实战：配置 Now Assist 管理控制台

### 首次访问

```
All → Now Assist Admin → Features
   → 从侧边栏点击 Employee
   → 确保顶部产品选择为 HRSD
```

**界面说明**:
```
Now Assist Admin Console
├── Dashboard（用量概览、技能状态）
├── Features（技能激活和管理）
│   ├── Case Assist（案例摘要 + 解决备注）
│   ├── Chat Assist（对话摘要）
│   ├── Knowledge（KB 生成）
│   ├── AI Search（搜索增强）
│   └── Agentic Workflows（代理工作流）
├── Skills（自定义技能管理）
├── Prompt Studio（提示词管理）
├── Settings（全局设置）
└── Monitoring（监控和审计）
```

### Step 1 — 激活 Case Summarization（案例摘要）

**操作步骤**:
```
Now Assist Admin → Features → Employee
   → Case Assist card → View details
   → Case Summarization → Activate skill
```

**配置详情**:
| 步骤 | 操作 | 说明 |
|------|------|------|
| 1. View Input | 检查输入模板（只读） | 基于案例状态的模板：New/WIP/Resolved |
| 2. Define Availability | 选择 Always enabled | 或配置条件触发 |
| 3. Select Display | 勾选 In-product + Now Assist Panel | 确保 sn_hr_core.basic 在角色列表中 |
| 4. Review & Activate | 点击 Activate | ✅ 激活成功 |

> 💡 **提示**: 从 Xanadu 版本开始，可以使用 Prompt Configurability 功能编辑案例摘要的提示词：`Now Assist Admin → Prompt Studio → 选择 Case Summarization → 编辑`

### Step 2 — 激活 Resolution Notes Generation（解决备注）

**操作步骤**:
```
Now Assist Admin → Features → Employee
   → Case Assist card → View details
   → Resolution Notes Generation → Activate skill
```

**关键配置**:
- **触发条件**: 默认在案例状态变为 "Closed Complete" 时自动触发
- **显示位置**: 建议同时勾选 In-product 和 Now Assist Panel
- **角色**: 确认 sn_hr_core.basic 在列表中

**工作流程**:
```
HR 代理处理案例 → 案例状态改为 Closed Complete
    → AI 自动生成解决备注
    → 代理可以 Accept（采纳）或 Edit（编辑后保存）
```

### Step 3 — 激活 Chat Summarization（对话摘要）

**操作步骤**:
```
Now Assist Admin → Features → Employee
   → Chat Assist card → View details
   → Chat Summarization → Activate skill
```

**对话摘要类型**:
| 类型 | 触发时间 | 内容 |
|------|---------|------|
| **VA Handoff Summary** | VA 转接人工时 | 汇总 VA 对话的关键信息 |
| **Chat Wrap-up Summary** | 实时聊天结束时 | 加速填写解决备注 |

**发布 HR Topic**（如果还未发布）:
```
确保 Scope = "HR Service Delivery Virtual Agent Conversations"
   → Virtual Agent → Topics → 找到 HR Topic → Publish
```

### Step 4 — 激活 KB Generation（知识文章生成）

**操作步骤**:
```
Now Assist Admin → Features → Employee
   → Knowledge card → View details
   → 在 "All available Knowledge skills" 中选择 → Activate Skill
```

**关键配置**:
- **触发条件**: 默认 "Closed Complete"（案例关闭时触发）
- **表格和字段**: 系统预定义（只读模式）
- **可用性**: 建议 Always enabled

**工作流程**:
```
案例解决关闭 → AI 基于案例内容生成知识文章草稿
    → HR 代理审阅 → 编辑完善 → 发布为正式知识文章
```

## 2.3 核心概念：RAG 架构详解

### 它不是"搜索"，而是"搜索+理解"

Now Assist in AI Search 使用 **检索增强生成（RAG）**，不是简单的关键词搜索。

### 完整流程图

```
员工提问："我的年假还剩几天？"
    ↓
1. AI Search 检索
    ├── 编码查询字符串预过滤（只检索 HR 知识库）
    ├── 仅检索 "Approved for Now Assist" 标记的文章
    ├── 混合搜索：
    │   ├── 关键词搜索（BM25 算法，精确匹配）
    │   └── 语义搜索（Embedding 向量，理解意图）
    └── 返回 Top N 结果
    ↓
2. 结果增强
    ├── 用户原始查询
    ├── 检索到的知识文章 HTML 内容
    └── 用户上下文（权限、部门等）
    ↓
3. Now LLM 生成
    ├── 基于检索内容生成自然语言答案
    └── 附上引用来源
    ↓
员工看到：Genius Result Card
    ├── 答案："根据公司政策，您目前剩余年假 12 天。"
    └── 来源：[2026 年休假政策.pdf] [年假 FAQ]
```

### 配置 AI Search 数据源

```
All → AI Search → Administration
   → 配置搜索数据源
```

**关键配置项**:
| 配置 | 说明 | 建议 |
|------|------|------|
| **Knowledge Base 索引** | 选择需要纳入 AI Search 的知识库 | 所有 HR 相关的 KB |
| **编码查询字符串** | 预过滤条件 | 按 COE 或部门隔离 |
| **Approved for Now Assist** | 文章级标记 | 只标记高质量内容 |
| **Result Improvement Rules** | 提升特定内容排名 | 对常见问题配置 |
| **External Content Connectors** | SharePoint/Confluence 爬取 | 如有需要 |

## 2.4 实战：配置 Agentic AI Workflows

### 架构总览

```
AI Agent Studio
├── Agentic Workflows（开箱即用工作流）
│   ├── Predict Service and Transfer HR Case
│   ├── Resolve Non-Critical HR Case
│   └── Resolve Critical HR Case
├── AI Agents（单个代理）
├── Orchestrator（编排器）
└── MCP Server Console
```

### Workflow 1: Predict Service and Transfer

**激活路径**:
```
AI Agent Studio → Overview → Agentic Workflows (view all)
   → 找到 "Predict service and Transfer HR case"
   → 激活
```

**工作流逻辑**:
```
员工提交请求（Portal/Email/Chat）
    → Record Field Value Predictor 预测服务类型
    → HR Case Transfer Agent 路由到正确的 HR Service
    → 案例自动分配给对应团队
```

**依赖**:
- Predictive Intelligence 插件
- 已配置的 COE 和 HR Service

### Workflow 2: Resolve Non-Critical HR Cases

**激活路径**:
```
AI Agent Studio → Overview → Agentic Workflows (view all)
   → 找到 "resolve noncritical HR case"
   → 激活
```

**涉及 Agent**:
| Agent | 功能 |
|-------|------|
| HR Criticality Detection Agent | 评估案例关键性（非关键 / 关键） |
| HR Search & Notify Agent | 检索知识库 + 目录项，通知员工 |

**工作流逻辑**:
```
案例创建
    → Criticality Detection Agent 评估
    ├── 非关键 → Search & Notify Agent
    │   → 检索知识文章 + 服务目录
    │   → AI 生成响应 → 员工自助解决
    │   → 案例自动关闭
    └── 关键 → 转人工处理
```

### Workflow 3: Resolve Critical HR Cases

**激活路径**:
```
AI Agent Studio → Overview → Agentic Workflows (view all)
   → 找到 "resolve critical HR case"
   → 激活
```

**涉及 Agent**:
| Agent | 功能 |
|-------|------|
| HR Case Planner Agent | 基于 Fulfillment Instructions + KB + FAQ 生成计划 |
| Next Best Action Recommender | 基于类似历史案例推荐步骤 |

**工作流逻辑**:
```
HR 代理打开案例 → 点击 "Generate Plan" UI Action
    → Case Planner Agent
    ├── 有 Fulfillment Instructions → 基于指导文件生成计划
    └── 无 Fulfillment Instructions → Next Best Action
        → 基于类似历史案例推荐
    → HR 代理审查 → 编辑细化 → 执行
```

**确保 "Generate Plan" 按钮出现在 Agent Workspace**:
```
All → System UI → UI Actions
   → 搜索 "Generate plan"
   → 打开记录
   → 在 Workspace 区域，确保以下两项勾选：
      □ Workspace form button
      □ Format for Configurable Workspace
```

> ⚠️ **关键提醒**: "These OOB Agentic workflows as of the December 2025 store release work for all COEs except Employee Relations and Lifecycle events." — Employee Relations 涉及敏感数据，Agent 默认不处理。

### 配置 Fulfillment Instructions（关键！）

如果缺少 Fulfillment Instructions，Case Planner Agent 将无法生成有效的解决计划。

**配置路径**:
```
HR Administration → HR Service Configuration
   → 选择 HR Service → Fulfillment Instructions Tab
   → 添加指导文件（政策文件、SOP、FAQ 等）
```

**最佳实践**:
- 每个 HR Service 至少配置 1-2 份 Fulfillment Instructions
- 使用知识文章作为补充源
- 定期更新以保持准确性

## 2.5 AI Voice Agents — 配置入门

### 架构
```
员工打电话 → CCaaS（Genesys Cloud / Twilio）
    → AI Voice Agent 处理语音
    → 调用 RAG + Now LLM
    → 语音合成返回
```

### 配置路径
```
AI Agent Studio → Settings → Voice Service
   → Add Voice Agent
   → 选择 AI Agent（如 PTO Query Agent）
   → 选择语言（支持 8 种语言）
   → 配置电话号码
   → 设置认证方式（Soft PIN / Okta / 语音识别）
   → 配置通话参数
   → 测试
```

### 支持场景

| 场景 | 员工说 | 系统做 |
|------|--------|--------|
| 创建新案例 | "我要请年假" | 创建 HR Case → 路由到对应团队 |
| 查询状态 | "我的离职申请到哪了？" | 查询案例状态 → 语音播报 |
| PTO 查询 | "我还有几天年假？" | 查 HR Profile → 返回余额 |
| 政策问答 | "产假是多少天？" | RAG 检索 → 返回答案 |

## 2.7 最佳实践与避坑

### 启动策略

```
Phase 1: 被动式功能（安全启动）
├── Case Summarization ← 从这里开始
├── Resolution Notes Generation
└── Chat Summarization

Phase 2: 搜索增强
├── Now Assist in AI Search
└── KB Generation

Phase 3: 主动式 AI
├── Predict & Transfer Workflow
└── Resolve Non-Critical Workflow

Phase 4: 高级功能
├── Resolve Critical Workflow
├── AI Voice Agents
└── AI Agent Fabric
```

### 常见坑汇总

| 坑 | 后果 | 解决方案 |
|----|------|----------|
| 自定义核心 HR 表字段 | AI 功能失效、升级困难 | 尽量配置而非自定义；评估影响 |
| 知识库未审计直接启用 AI | AI 回答不准确 → 员工不信任 | 启动前做内容审计 |
| 未勾选 "Approved for Now Assist" | AI 看不到内容 → 返回空结果 | 配置文章标记 |
| HR Case 缺少详细信息 | 摘要和解决备注质量差 | 加摘要加章节标题，丰富案例内容 |
| 跳过 Readiness Check | 部署后发现兼容性问题 | 使用诊断工具提前发现 |
