## 1. 产品概述

### 1.1 产品定位
JobAgent 是一款面向申请欧美职位的求职者的全流程 AI 助手，提供从简历管理、职位监控、AI 定制优化、半自动申请到状态跟踪与统一收件箱的端到端解决方案。核心设计理念为**人机协同（Human-in-the-loop）**：所有关键决策（申请提交、回复发送）均需用户确认。

### 1.2 目标用户
- **主要用户**：申请欧美公司职位的求职者（留学生、海归、国际求职者）
- **语言偏好**：英文为主，中文辅助
- **付费能力**：愿意为提升申请效率与质量付费的求职者

### 1.3 商业模式
- **免费版**：20 次申请额度，基础简历管理与职位监控
- **付费订阅**：无限申请、高级 AI 优化（多版本对比、深度定制）、收件箱 AI 跟进、优先客服

### 1.4 平台优先级
1. **P0 阶段**：Web 应用（响应式设计，桌面 + 移动端浏览器）
2. **P1 阶段**：微信小程序（面向中文用户）
3. **P2 阶段**：Facebook Messenger / WhatsApp 集成（通知与快捷操作）

## 2. 核心功能需求

### 2.1 简历中心 (Resume Hub)

#### 2.1.1 基础 Profile 管理
**功能描述**：用户维护一份主 Profile，包含 8 大核心模块，支持中英双语字段并存。

| 模块 | 字段示例 | 数据结构 |
|------|---------|---------|
| **基本信息** | 姓名、职业标签、个人简介 | JSON：`{"en": {...}, "zh": {...}}` |
| **联系信息** | 邮箱、电话、LinkedIn、GitHub、所在城市 | 单一语言即可 |
| **教育经历** | 学校、学位、专业、时间、GPA、重点课程/成就 | 独立表，支持多条，每条支持双语 |
| **工作经历** | 公司、职位、时间、地点、工作内容（bullet points） | 独立表，每条 bullet 支持双语 |
| **个人技能** | 技能名称、熟练度、使用年限 | 列表结构 |
| **推荐信息** | 推荐人姓名、职位、联系方式、关系 | 列表结构 |
| **求职意向** | 目标职位、行业、地点、远程偏好、签证状态 | JSON |
| **期望薪资** | 货币、最低/期望值、周期（年薪/时薪） | JSON |

**用户操作流程**：
1. 首次使用：上传简历（PDF/DOCX）→ AI 解析 → 用户校对确认
2. 日常维护：在线编辑器逐模块填写/更新，自动保存

#### 2.1.2 简历上传与解析
**输入格式**：PDF、DOCX  
**解析流程**：
1. 文本抽取（PyMuPDF / python-docx）
2. DeepSeek API 结构化解析（Prompt 指定 8 大模块的 JSON Schema）
3. 返回解析结果 + 置信度分数
4. 前端呈现解析结果，用户逐字段校对、修改、确认

**验收标准**：  
- 字段级准确率 ≥ 90%（基于 100 份真实简历测试集）
- 中文简历解析准确率 ≥ 85%
- 解析时长 ≤ 10 秒（P95）

#### 2.1.3 在线编辑器
**功能要求**：
- 分模块表单编辑（响应式布局，移动端友好）
- 实时自动保存（防丢失）
- 双语字段切换（英文/中文 tab）
- 富文本编辑器支持（工作经历的 bullet points）
- 拖拽排序（教育/工作经历）

#### 2.1.4 多版本管理
**概念模型**：
- **1 个基础 Profile**：用户维护的主数据源
- **N 个申请版本（Resume Versions）**：每次针对特定职位生成的定制版本，不可变快照

**版本元数据**：
- 版本名称（用户自定义或自动生成，如 "Software Engineer @ Google"）
- 语言（en / zh）
- 关联的目标职位
- 创建时间
- AI 修改日志（diff）

**用户操作**：
- 查看所有版本列表
- 对比版本差异（diff 视图）
- 下载版本为 PDF
- 删除版本

#### 2.1.5 AI 定制优化
**触发场景**：用户选择目标职位 → 点击"生成定制简历"

**AI 处理流程**：
1. 输入：基础 Profile + 目标 JD 文本
2. DeepSeek 执行：
   - 关键词对齐（从 JD 提取要求，在简历中强化相关技能/经历）
   - 工作经历重排（最相关的经历前置）
   - Bullet points 优化（量化成果、动词开头、符合欧美简历惯例）
   - 技能匹配度评估
3. 输出：新版本 + diff 变更日志（高亮修改部分）
4. 用户审核：逐条接受/拒绝/修改 AI 建议

**特殊功能：中→英翻译改写**  
- 用户基础 Profile 为中文 → 一键生成英文申请版本
- 非直译，而是本地化改写：
  - 移除照片、婚姻状况、身份证号等欧美简历不需要的字段
  - 调整格式（动词开头、量化成果）
  - 文化适配（如中国公司名称加英文注释）

**验收标准**：
- 人工评审通过率 ≥ 80%（由 10 名目标用户评审 50 份 AI 优化简历）
- 关键词覆盖率：JD 中核心技能在简历中出现率 ≥ 90%

#### 2.1.6 简历导出
**输出格式**：ATS 友好的 PDF（单栏、无表格、标准字体 Arial/Calibri）  
**模板选项**：
- 美式简历（US Letter 8.5x11 英寸）
- 国际简历（A4）
- 极简 / 专业 / 学术风格（用户可选）

**技术方案**：LaTeX 模板 + Jinja2 变量替换 + pdflatex 编译，或使用 WeasyPrint（HTML → PDF）

### 2.2 职位监控与匹配 (Job Tracking & Matching)

#### 2.2.1 平台接入优先级

| 优先级 | 平台 | 接入方式 | 备注 |
|-------|------|---------|------|
| **P1** | SmartRecruiters | 官方 Posting API + Apply API | 唯一官方支持程序化申请的主流 ATS |
| **P1** | SuccessFactors | 公开招聘门户抓取（Playwright） | 需模拟浏览器，合规风险中等 |
| **P2** | Greenhouse | 公开 Job Board API | 官方 API 仅查询，申请需跳转 |
| **P2** | Lever | 公开 Postings API | 同上 |
| **P2** | Workday | 招聘门户抓取（高风险） | 反爬严格，建议后期评估 |
| **P3** | Moka（国内） | 官方 API（需企业授权） | 仅在拓展国内市场时接入 |

#### 2.2.2 监控任务配置
**用户输入**：
- 目标公司列表（支持模糊匹配）
- 关键词（职位名称、技能）
- 地点（支持多地点、远程）
- 职级（Entry / Mid / Senior / Lead）
- 更新频率（默认 30 分钟轮询）

**后台任务**：
- 定时抓取各平台新职位
- 去重（基于 `external_id`）
- 存储原始数据 + 结构化字段

#### 2.2.3 匹配引擎
**输入**：用户的求职意向 + 职位 JD  
**处理流程**：
1. **粗筛**：关键词匹配（职位名称、必需技能）
2. **精筛**：
   - 文本 Embedding（使用 DeepSeek Embedding API 或开源模型如 bge-large-en）
   - 计算用户 Profile 与 JD 的语义相似度
3. **LLM 复核**：高相似度职位送 DeepSeek 生成匹配理由（为什么适合/不适合）
4. **输出**：匹配分数 0-100 + 匹配理由（3-5 条要点）

**验收标准**：
- 匹配分数与人工标注一致率 ≥ 85%（基于 200 个职位-用户对的测试集）
- 误报率（推送不相关职位）≤ 10%

#### 2.2.4 推送通知
**触发条件**：匹配分数 ≥ 用户设定阈值（默认 70）  
**推送渠道**：
- Web：浏览器通知 + 站内消息中心
- 微信小程序：订阅消息（需用户授权）
- Email：每日摘要（可选）
- WhatsApp/Facebook（P2 阶段）：即时通知

### 2.3 半自动申请 (Semi-Automated Application)

#### 2.3.1 核心原则
**人机协同**：所有申请在提交前必须经过用户确认，系统仅完成预填和生成定制简历。

#### 2.3.2 申请流程

**Step 1: 用户选择职位**  
从职位列表或匹配推送中选择目标职位 → 点击"申请"

**Step 2: 生成定制简历**  
- 自动触发 AI 定制优化（2.1.5）
- 用户审核 diff → 确认或修改 → 保存为新版本

**Step 3: 预填申请表单**  
根据平台类型：
- **SmartRecruiters**：直接调用 Apply API，传递结构化数据（姓名、邮箱、简历附件、回答问题）
- **其他平台**：
  - 后台用 Playwright 模拟访问申请页面
  - 识别表单字段（文本框、下拉菜单、单选框）
  - 从用户 Profile 提取数据预填（如"请输入工作年限" → 从工作经历计算）
  - 截图表单 → 返回前端

**Step 4: 用户确认**  
前端展示：
- 职位信息卡片
- 使用的简历版本（可切换）
- 预填的表单数据（可编辑）
- 常见问题的 AI 推荐答案（如"Why do you want to join us?" → DeepSeek 生成草稿）

用户逐项审核 → 修改（如需） → 点击"提交"

**Step 5: 提交**  
- SmartRecruiters：API 提交
- 其他平台：Playwright 填充表单 + 点击提交按钮（需用户实时授权会话）

**Step 6: 记录**  
保存申请快照（提交时间、使用的简历版本、表单内容）→ 状态设为 `submitted`

#### 2.3.3 额度管理
- 免费用户：20 次申请额度，每次提交消耗 1 次
- 付费用户：无限次
- 额度用尽后：提示升级或等待下月重置（免费额度不累积）

#### 2.3.4 验收标准
- **SmartRecruiters API 申请成功率 ≥ 95%**（P95 延迟 ≤ 5 秒）
- **表单预填字段准确率 ≥ 95%**（基于 50 个不同公司的申请页面测试）
- **用户确认流程 UAT**：10 名用户完成端到端申请，无阻断性缺陷

### 2.4 状态跟踪与统一收件箱 (Status Tracking & Unified Inbox)

#### 2.4.1 状态跟踪
**数据来源**：
1. **邮件解析**（主要方式）：
   - 用户授权绑定邮箱（IMAP 访问）
   - 后台定时拉取新邮件（5 分钟间隔）
   - 识别关键邮件类型：
     - 申请确认（"Application received"）
     - 面试邀请（"Interview invitation"）
     - 拒信（"We regret to inform"）
     - Offer（"Congratulations"）
   - 提取关键信息（公司、职位、时间、下一步动作）
   - 关联到对应的 Application 记录

2. **平台 API**（补充）：
   - SmartRecruiters：Application Status API
   - 其他平台：如有公开 API 则定时查询

**状态模型**：
- `draft`：预填完成，待用户确认
- `submitted`：已提交
- `viewed`：HR 已查看
- `interview`：面试阶段
- `offer`：收到 offer
- `rejected`：被拒绝
- `withdrawn`：用户撤回

**状态历史**：每次变更记录时间戳、来源（email / API / 用户手动）

#### 2.4.2 统一收件箱
**功能**：将所有申请相关的邮件和站内消息聚合到一个界面，按申请线程分组。

**界面结构**：
- 左侧：申请列表（按公司分组或按时间排序）
- 右侧：消息线程（类似邮件客户端）
  - 显示与该申请相关的所有邮件（收/发）
  - 平台站内消息（如有）以卡片形式显示 + 深链跳转原系统

**消息类型**：
- 邮件（双向：收到的 + 用户发出的）
- 平台站内消息（只读，跳转原系统回复）

#### 2.4.3 回复功能
**邮件回复**：
- 用户可在统一收件箱内直接回复邮件
- AI 辅助生成草稿：
  - 场景识别（面试确认、感谢信、跟进询问）
  - DeepSeek 生成草稿（语气可选：formal / friendly）
  - 用户编辑 → 确认发送

**平台站内消息回复**：
- 方案 A（理想）：通过平台 API 代发回复（需平台支持且用户授权）
- 方案 B（兜底）：提供深链跳转到原系统，用户手动回复

#### 2.4.4 AI 跟进建议
**触发场景**：
- 申请后 7 天无回复 → 提示"要不要发封跟进邮件？"
- 面试后 3 天 → 提示"发封感谢信？"

**AI 生成内容**：
- 根据申请阶段和时间差，生成定制邮件草稿
- 用户确认后发送

#### 2.4.5 验收标准
- **邮件状态识别准确率 ≥ 90%**（基于 500 封真实招聘邮件测试集）
- **消息同步延迟 ≤ 5 分钟**（P95）
- **消息零丢失**：与用户邮箱对比，遗漏率 = 0
- **AI 回复草稿通过率 ≥ 80%**（10 名用户评审 100 份草稿）

## 3. 技术架构

### 3.1 技术栈

| 层级 | 技术选型 | 说明 |
|------|---------|------|
| **前端（Web）** | React 18 + TypeScript + Vite | 响应式设计，支持桌面 + 移动浏览器 |
| **前端（小程序）** | Taro + React（跨端方案） | 编译为微信小程序 |
| **后端** | FastAPI (Python 3.11+) | 异步支持、自动生成 OpenAPI 文档 |
| **数据库** | SQLite（起步）→ PostgreSQL（生产） | 快速原型 → 可扩展 |
| **ORM** | SQLAlchemy 2.0 + Alembic | 迁移管理，支持 SQLite 和 PostgreSQL |
| **任务队列** | APScheduler（起步）→ Celery + Redis（生产） | 职位抓取、邮件同步等定时任务 |
| **浏览器自动化** | Playwright（Python） | 表单预填、平台抓取 |
| **LLM** | DeepSeek API（已备案） | 简历解析、优化、匹配、回复生成 |
| **邮件** | imaplib（IMAP）+ smtplib（SMTP） | 收件箱集成 |
| **文件存储** | 本地文件系统（起步）→ AWS S3 / 阿里云 OSS | 简历 PDF 存储 |
| **部署** | Docker + Docker Compose | 环境一致性 |
| **CI/CD** | GitHub Actions | 自动测试 + 部署 |

### 3.2 数据模型核心表

#### 核心实体关系
```
User (用户)
  ├── Profile (基础简历)
  │     ├── Education (教育经历，1:N)
  │     └── WorkExperience (工作经历，1:N)
  ├── ResumeVersion (申请版本，1:N)
  ├── WatchTask (监控任务，1:N)
  ├── Application (申请记录，1:N)
  │     └── MessageThread (消息线程，1:1)
  │           └── Message (消息，1:N)
  └── MailboxAccount (邮箱账户，1:N)

JobPosting (职位)
  └── MatchResult (匹配结果，N:N with User)
```

#### 关键表结构（简化版）

**users**
- id, wx_openid, email, locale (en/zh), plan (free/pro), apply_quota_used

**profiles**
- id, user_id, basic_info (JSON), contact_info, skills, references, job_intent, salary_expectation

**educations**
- id, profile_id, school (JSON: en/zh), degree, major, start_date, end_date, gpa, highlights, sort_order

**work_experiences**
- id, profile_id, company (JSON), title (JSON), location, start_date, end_date, bullets (JSON), sort_order

**resume_versions**
- id, user_id, name, language (en/zh), content_snapshot (JSON), target_job_id, ai_change_log (JSON), pdf_path

**job_postings**
- id, source (smartrecruiters/successfactors/...), external_id, company_name, title, location, remote_type, jd_text, apply_url, posted_at, raw (JSON)

**watch_tasks**
- id, user_id, companies (JSON), keywords (JSON), locations (JSON), min_match_score, is_active

**match_results**
- id, user_id, job_id, score (0-100), reasons (JSON), notified (bool)

**applications**
- id, user_id, job_id, resume_version_id, status (enum), submitted_payload (JSON), submitted_at, status_history (JSON)

**mailbox_accounts**
- id, user_id, email, imap_host, credentials_encrypted (AES), is_active

**message_threads**
- id, user_id, application_id, subject, channel (email/platform), external_link (深链)

**messages**
- id, thread_id, direction (in/out), body, ai_draft, sent_at
