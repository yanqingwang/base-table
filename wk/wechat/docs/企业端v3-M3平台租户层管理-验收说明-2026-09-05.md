## 一、本次交付

### 1. 数据模型
- `Merchant` 新增字段：`status`（active / suspended，server_default="active"），由 `db.migrate()` 向前兼容自动补列
- 新增 `PlatformAdmin` 表（id, name, note, createdAt），用于平台运营账号；演示仓固定 id=1「平台运营·超管」

### 2. 后端接口（`/api/platform/*`，鉴权：`X-Platform-Admin: <id>`）
| 方法 | 路径 | 行为 |
|---|---|---|
| GET | `/api/platform/merchants` | 租户（企业）列表：名称/法人/行业/状态/管理员/门店数/员工数/卡数/开通时间 |
| POST | `/api/platform/merchants` | 开通新企业：body `{ name, adminName, industry?, contactPhone?, legalName?, idempotencyKey? }`，自动建 Merchant(status active) + 角色「企业管理员」 + 首位授权管理员 Staff(isOwner) 并写入 `Merchant.admins`；幂等 |
| PATCH | `/api/platform/merchants/<id>/status` | body `{ status: active\|suspended }`，审计日志 `platform.merchant.status`，重复停用幂等（changed=false），未知企业 404 |

### 3. 强制执行点
- `services.ensure_permission()` 加固：员工有操作权限时若其所属 `Merchant.status == "suspended"`，一律返回 `403 "企业已被平台停用，禁止操作"`（覆盖所有写操作与权限相关接口）
- 平台路由 `_require_platform(session)`：无 `X-Platform-Admin` 头 / 头值查不到 PlatformAdmin → `403 "仅平台管理员可操作"`（商户端员工 X-Staff-Id 调平台接口也被拒）

### 4. 前端（web/app.js + web/index.html）
- 顶部「当前身份」新增 **「平台超管（租户管理）」**
- TABS.platform = `[{ id: "tenants", label: "租户管理", fn: tabTenants }]`
- `tabTenants()`：开通表单（企业名称/管理员姓名/行业/电话）+ 企业列表卡片（管理员/门店数/员工数/卡数/状态徽标/停用-启用按钮）
- `roleHeaders()` 新增 `platform → X-Platform-Admin: <id>`，与商户端/顾客端鉴权完全隔离

## 三、线上 / 本地冒烟

### HTTP（演示服务 http://127.0.0.1:8090）
```
GET  /api/platform/merchants  (H: X-Platform-Admin: 1) → 200
POST /api/platform/merchants  body={name, adminName, ...}   → 200 {merchantId, adminStaffId, ...}
PATCH /api/platform/merchants/<mid>/status {status:"suspended"} → 200 changed=true
POST /api/merchant/card-templates H: X-Merchant-Id=<mid>, X-Staff-Id=<adminStaffId>
   → 403 "企业已被平台停用，禁止操作"
```
