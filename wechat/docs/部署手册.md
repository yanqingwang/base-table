# 部署手册（次卡管家 · 微信云托管 / 小程序）

> 完整命令与两仓库陷阱速查。会话级详细记录见 `memory/work.md` 顶部「📌 快速开始」。

## 1. 网页 / 后端部署（云托管自动构建）

```bash
cd code/card-counter-flask

# 只 add 源码，勿 git add -A（card_counter.db / __pycache__/* 被 git 跟踪，提交会带入脏数据）
git add wxcloudrun/views.py wxcloudrun/dao.py wxcloudrun/model.py wxcloudrun/__init__.py wxcloudrun/templates/index.html
git commit -m "说明"
git push origin main        # 云托管读此仓库 main 分支自动构建
```

### ⚠️ 两仓库陷阱（关键）
- `code/card-counter-flask/` 是**独立 git 仓库**（`origin=github.com/yanqingwang/card-counter-flask.git`），**云托管只读它**。
- 它同时被父仓库 `base-table` 作为普通文件跟踪。**只推父仓库 `python` 分支不会部署**。
- 父仓库提交仅作版本记录，网页/小程序改动后记得补提交。

### 云托管未自动重建时
追加空提交强制触发 webhook：
```bash
git commit --allow-empty -m "chore: 触发云托管重建" && git push origin main
```
重建通常需 2~5 分钟；验证方式：
```bash
curl -s https://flask-z9hh-281177-5-1453124923.sh.run.tcloudbase.com/ | grep <特征串>
```

## 2. 小程序上传（miniprogram-ci）

```bash
cd code/card-counter-miniapp
NODE_PATH=$(npm root -g) node scripts/upload_ci.js <版本> "<描述>"
# 例：NODE_PATH=$(npm root -g) node scripts/upload_ci.js 2.4.8 "feat: 修改签到支持备注+日期"
```

### 上传前检查（两个必查项）
1. **private.key md5** 必须为 `ff454fb9596f8e95d686acdd03878de2`
   - 该文件会被 joplin/obsidian 同步**覆盖回旧版**，污染后从 `~/下载/private.wx9c5974ab24d057c3 (1).key` 恢复
2. **出口 IP 在白名单**：小程序后台「开发管理 → 开发设置 → 代码上传白名单」
   - 开启代理后出口 IP 会变（如 185.248.186.60），需临时加入

### 常见上传错误
- `Cannot find module 'miniprogram-ci'` → `NODE_PATH=$(npm root -g)` 缺失（包是全局安装）
- TLS 抖动失败 → 直接重试即可（同一版本号重复上传无害）

## 3. 提交审核 + 发布（人工，无法脚本化）
微信公众平台后台版本管理页由 **wujie 微前端**加载，CDP 自动化无法操作（shadow DOM 不加载应用 JS），**必须人工**：

1. mp.weixin.qq.com → 管理 → 版本管理 → 开发版本
2. 选最新开发版（如 v2.4.8）→ 提交审核（勾选协议 + 处理接口配置/安全测试弹窗）
3. 审核通过后 → 审核版本 → 发布

## 4. 常见坑汇总
| 坑 | 说明 | 应对 |
|----|------|------|
| 工作区被外部同步污染 | joplin/obsidian 把工作区文件回滚到旧版 | 每次提交前 `git diff HEAD --stat` 核对文件行数；关键文件改完立即 commit+push |
| private.key 被覆盖 | 同上 | 上传前查 md5 |
| 代理改出口 IP | git push / miniprogram-ci 均受影响 | 加白名单或临时关代理 |
| 云托管构建延迟 | 内容 push 偶尔不触发 | 追加空提交强制触发 |
