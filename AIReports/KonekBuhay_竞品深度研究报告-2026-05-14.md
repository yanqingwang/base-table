### 2.2 核心功能模块详细说明

#### 模块A：招聘方端（Recruiter Side）

##### A.1 Candidate Tracking System (CTS) — 候选人追踪系统

- **多职位管理**：在一个仪表盘内统一管理多个职位的所有候选人
- **替换手动流程**：替代传统Excel表格/纸笔记录/分散的messaging app记录
- **管道可见性**：清晰展示招聘管道各阶段状态（投递→筛选→面试→录用）
- **全流程控制**：从候选人进入到最终录用，每个阶段可追踪可操作

##### A.2 AI简历解析（AI Resume Parsing）

- **自动提取关键信息**：从蓝领工人简历/申请表中提取工作经验、技能、教育背景等
- **非结构化→结构化**：将非标准格式的简历转化为结构化数据
- **本地语言支持**：支持菲律宾英语和他加禄语混合的简历

##### A.3 AI候选人筛选（AI Candidate Filtering）

- **条件匹配**：基于职位要求自动筛选符合条件的候选人
- **排序推荐**：按匹配度对候选人进行优先级排序
- **排除不匹配**：自动过滤明显不符要求的申请

##### A.4 AI验证（AI Basic Validation）

- **信息验证**：对候选人提交的信息进行基础验证
- **格式检查**：确保证件/经历信息格式正确
- **异常检测**：识别明显不合理的经验声明

##### A.5 AI报告（AI Reporting & Analytics）

- **招聘效率报告**：各职位的招聘进度、转化率
- **候选人来源分析**：追踪候选人来自哪些渠道
- **时间线分析**：从投递到录用的平均周期

#### 模块B：求职者端（Candidate Side）

##### B.1 Smart Resume — 智能简历

- **即時數位档案**：创建并维护一个实时更新的数字档案
- **跨职位一致性**：同一份简历可用于多个职位申请，信息保持一致
- **简化填写**：一次填写，多次使用，避免重复输入
- **移动端优先**：专为蓝领工人移动端使用习惯设计

### 2.3 产品特色分析

#### 核心差异化特征

| 特征 | 描述 | 蓝领适用性 |
|------|------|-----------|
| **AI辅助而非替代** | AI处理重复筛选工作，人工做决策 | 🟢 降低招聘方负担 |
| **集中化管道** | 所有职位统一管理 | 🟢 适合批量招聘场景 |
| **简化求职者体验** | 智能简历一次填写永久使用 | 🟢 蓝领群体数字门槛低 |
| **移动优先设计** | 不依赖PC端操作 | 🟢 菲律宾移动普及率高 |

#### 与白领ATS的区别

| 维度 | 白领ATS（如Greenhouse/Lever） | KonekBuhay |
|------|-------------------------------|------------|
| 目标用户 | 白领/专业技术人员 | 蓝领/体力劳动者 |
| 简历格式 | PDF/DOCX长格式 | 简化的结构化信息 |
| 筛选重点 | 学历、经验年限、项目 | 技能标签、可用性、培训记录 |
| 招聘量级 | 单职位<50人 | 单职位50-500+人 |
| 决策速度 | 多轮面试，2-4周 | 快速筛选，1周内出结果 |
| 候选人触达 | 邮件+LinkedIn | WhatsApp+短信+电话 |
| UI复杂度 | 功能丰富但复杂 | 极简，图文导向 |

## 3. 技术架构推测

基于公开发布信息、LinkedIn数据、行业模式和官方网站公开信息，推测KonekBuhay的技术架构如下：

### 3.1 推测技术栈

| 层级 | 推测技术 | 依据 |
|------|---------|------|
| **前端** | React / Next.js | 现代SaaS标准选择，开发者生态丰富 |
| **后端** | Node.js (Express/NestJS) 或 Python (FastAPI) | AI/ML处理需要Python生态；API服务需快速开发 |
| **数据库** | PostgreSQL + Redis | 关系数据+缓存/会话管理 |
| **AI/ML** | Python + LangChain/LLM (GPT-4/Claude) | 简历解析、筛选、报告生成需要LLM能力 |
| **部署** | AWS / GCP / Philippine本地云 | 东南亚通用选择 |
| **移动端** | React Native / PWA | 专注移动优先体验 |
| **CI/CD** | GitHub Actions + Docker | 标准SaaS实践 |

### 3.2 AI能力深度分析

基于产品描述，推测AI模块的构成：

```
用户提交简历/信息
        │
        ▼
┌─────────────────────────────────────────┐
│           AI Resume Parsing              │
│  ├ NLP: 提取实体（技能、经验、位置）       │
│  ├ OCR: 如简历为图片则先图片转文字         │
│  └ 标准化: 输出统一Schema                │
└────────────────────┬────────────────────┘
                     │
                     ▼
┌─────────────────────────────────────────┐
│         AI Candidate Filtering           │
│  ├ 硬性条件过滤（地理位置、签证状态）      │
│  ├ Match Score计算（技能匹配度）          │
│  └ 排序输出候选池                        │
└────────────────────┬────────────────────┘
                     │
                     ▼
┌─────────────────────────────────────────┐
│        AI Validation                    │
│  ├ 格式校验（电话号码、日期格式等）        │
│  ├ 一致性检查（工作经验时间线合理性）      │
│  └ 异常标记（需要人工复核）               │
└────────────────────┬────────────────────┘
                     │
                     ▼
┌─────────────────────────────────────────┐
│         AI Reporting                    │
│  ├ 招聘管道统计                          │
│  ├ 候选人画像                            │
│  └ 招聘效率洞察                          │
└─────────────────────────────────────────┘
```

**关键推测**：KonekBuhay的AI能力很可能基于大型语言模型（LLM）构建，而非传统规则引擎。原因：
1. 蓝领简历格式不统一，规则引擎难以覆盖
2. 菲律宾英语+他加禄语混合文本需要NLP能力
3. 快速的MVP验证周期受益于LLM API而非自建模型

## 4. 市场定位与竞争分析

### 4.1 目标市场定义

**KonekBuhay 的核心目标市场：**
- **地理**：菲律宾（菲佣、制造业、建筑业、物流业密集的蓝领市场）
- **客户**：招聘方（企业HR、劳务中介、招聘负责人）
- **用户**：蓝领求职者（工厂工人、建筑工、物流工、服务人员）
- **行业**：制造业、建筑业、物流快递、零售服务、农业

### 4.2 市场痛点对应

| 痛点 | KonekBuhay方案 |
|------|---------------|
| 蓝领招聘依靠Excel+纸笔+短信 | CTS集中化数字化管理 |
| 简历格式不统一，信息难以提取 | AI简历解析 |
| 大量候选人手动筛选效率低 | AI过滤+排序推荐 |
| 蓝领工人无专业简历 | Smart Resume数字档案 |
| 招聘管道不透明 | 可视化管道仪表盘 |
| 重复信息录入 | 一次填写跨职位使用 |

## 8. 对DL Hire的启示

### 8.1 关键威胁

> **KonekBuhay已经验证了菲律宾蓝领招聘数字化的市场需求——同时也证明了时间窗口正在缩小。**

1. **先发劣势**：KonekBuhay已上线4个月，DL Hire如不加速将失去先机
2. **AI能力差距**：KonekBuhay的AI简历解析和筛选能力需要DL Hire投入资源追赶
