## 1.1 实战：激活 HRSD 环境

### Step 1 — 激活 HR Core 插件

这是所有 HRSD 功能的基础。插件 ID: `com.sn_hr_core`

**操作路径**:
```
All → System Definition → Plugins
   → 搜索 "com.sn_hr_core"
   → 点击 "Activate/Upgrade"
```

**依赖自动激活**:
- Human Resources Scoped App: Security
- Human Resources Scoped App: Integrations

> ⚠️ **常见坑**: 激活过程可能需要 10-15 分钟。如果使用个人开发者实例（PDI），内存限制可能导致激活失败 — 此时需到 `System Diagnostics → Instance Utilization` 确认内存充足。

**验证激活成功**:
```
All → 在导航过滤器中输入 "HR Administration"
   → 确认看到以下模块：
      ├── Case Management
      ├── Knowledge Management
      ├── COE Configuration
      ├── Manage Roles
      └── HR Service Configuration
```

### Step 2 — 确认应用范围（Scope）

HRSD 使用专用的 **Human Resources Scope**（应用范围），与 ITSM 的 global scope 不同。

**如何确认当前 Scope**:
```
All → 右上角当前应用名称 → 确认显示 "Human Resources"
   → 如果不是，点击切换 → 选择 "Human Resources" scoped app
```

> ⚠️ **关键提醒**: 在 HRSD 中做配置时，**必须确保处于 HR Scope**。在 global scope 下创建的表单/字段可能导致跨 scope 访问问题。Scope 错误 = 配置不可见。

## 1.2 实战：配置 COE 与 HR Service

### 理论认知

HRSD 的数据模型层次：
```
COE（卓越中心，如 Payroll / Benefits / Compensation）
  └── Topic Category（主题类别）
       └── Topic Detail（主题明细）
            └── HR Service（HR 服务，如 "薪资查询"）
                 └── HR Case（具体案例）
```

### Step 1 — 启用/创建 COE

COE 的配置有两种方式：

**方式 A：使用 OOTB（开箱即用）COE**
```
HR Administration → COE Configuration
   → 勾选需要启用的 COE（Payroll, Benefits, Employee Relations 等）
   → Save
```

**方式 B：创建新的 COE**（当 OOTB 不能满足时）
```
HR Administration → COE Configuration
   → 先创建 Topic Category（如 "国际派遣"）
   → 再创建 Topic Detail（如 "签证办理"）
   → 最后创建 HR Service
```

> ⚠️ **实施顾问的经验之谈**: 
> - "Going forward with Releases, you cannot toggle on a COE, you must first create a Topic Category, Topic Detail, and then create your HR Service(s)."
> - 当配置一个新的 COE 时，将缺失 OOTB COE 自带的 notifications、inbound actions、SLAs、assignment rules、contextual search、agent assist 等记录。**建议做法**：复制已有 COE 的记录，"Insert and Stay" 到新 COE 表，再添加特定配置。

### Step 2 — 创建 HR Service

```
HR Administration → HR Service Configuration → New
```

**必填字段**:
| 字段 | 填写示例 | 说明 |
|------|---------|------|
| **Name** | "薪资查询服务" | 服务的显示名称 |
| **COE** | Payroll | 所属卓越中心 |
| **Fulfillment Type** | Manual / Service Activity / Lifecycle Event | 实现方式 |
| **Topic Category** | Payroll Inquiry | 一级分类 |
| **Topic Detail** | Salary Statement | 二级分类 |
| **Default Handler** | HR Tier 1 Group | 默认处理组 |

**Fulfillment Type 的选择**:
| 类型 | 说明 | 适用场景 |
|------|------|----------|
| Manual | HR 代理手动处理 | 简单查询、政策解答 |
| Service Activity | 有标准子任务流程 | 审批流程、文件签署 |
| Lifecycle Event | 涉及多步骤的流程 | 入职、离职、转岗 |

> ✏️ **练习**: 创建 3 个 HR Service：
> 1. "请假查询" (COE: Benefits, 类型: Manual)
> 2. "入职手续办理" (COE: 新建一个 Onboarding COE, 类型: Lifecycle Event)  
> 3. "薪酬异议" (COE: Payroll, 类型: Service Activity)

## 1.3 实战：配置 HR Case Template

HR Case Template 的作用是预填充案例的字段、任务和 SLA。

### 创建模板
```
HR Administration → HR Case Templates → New
```

**关键配置项**:
| 字段 | 说明 |
|------|------|
| **Template Name** | 模板名称 |
| **COE** | 关联的卓越中心 |
| **Assignment Group** | 默认分配到哪组 |
| **Assignment Rule** | 自动分配规则 |
| **Priority** | 默认优先级 |
| **SLA** | 绑定服务级别协议 |
| **HR Template** | 可选的 HR Template（用于预填描述等） |

### 配置 Assignment Rules（自动分配）

HRSD 的案例自动分配分两步：

**Step 1: HR Skills（技能标签）**
```
HR Administration → Manage Roles → Skills → New
   → 创建技能如 "Payroll Specialist", "Benefits Expert"
   → 分配给对应 Group（Group 记录 → Skills related list）
```

**Step 2: HR Assignment Rules**
```
HR Administration → Assignment Rules → HR Assignment Rules
   → 配置条件（如 COE = Payroll → 分配到 Payroll Group）
```

**Step 3: Matching Rules（负载均衡）**
配置后，ServiceNow 会在指定的 Group 内，自动将案例分配给工作量最少的、具备对应技能的成员。

> ⚠️ **常见坑**: 
> - "Don't create the same fields on each COE table. For those that are used on multiple COEs, make use of table inheritance and create them on the core case table (sn_hr_core_case)."
> - 字段创建流程: 创建字段 → 添加到 form layout → 在 "Hide HR service fields" UI Policy 中添加 Visible=False → 在对应 HR Service 的 "Service table fields" 中添加新字段名

## 1.4 SKU 选型决策指南

> 以下数据来自 ServiceNow 官方 Welcome Guide + 社区资深顾问经验

### 三版本功能速查

| 功能 | Standard | Professional | Enterprise |
|------|----------|-------------|------------|
| HR Case Management | ✅ | ✅ | ✅ |
| Knowledge Management | ✅ | ✅ | ✅ |
| HCM Integration (Workday/SF/Oracle) | ✅ | ✅ | ✅ |
| COE Configuration | ✅ | ✅ | ✅ |
| **HR Agent Workspace** | ❌ | ✅ | ✅ |
| **Employee Center** (standard) | ❌ | ✅ | ✅ |
| **Virtual Agent for HR** | ❌ | ✅ | ✅ |
| **Lifecycle Events (HR-only)** | ❌ | ✅ | ✅ |
| **Enterprise Onboarding & Transitions** (跨部门) | ❌ | ❌ | ✅ |
| **Employee Center Pro** (高级门户) | ❌ | ❌ | ✅ |
| **Performance Analytics for HR** | ❌ | ❌ | ✅ |
| **Employee Journey Management** | ❌ | ❌ | ✅ |
| **Document Management** | ❌ | ❌ | ✅ |
| **Now Assist for HRSD** (附加许可) | ❌ | 附加 | 附加 |
| **Anonymous Report Center (ARC)** | ❌ | ✅ (HRSD Pro) | ✅ |

### 选型决策树

```
公司的 HR 流程是否需要跨部门协作（IT/设施/财务）？
├── 否 → 需要 HR Agent Workspace？
│   ├── 否 → Standard
│   └── 是 → Professional
└── 是 → 需要 Employee Center Pro / Journey Management？
    ├── 否 → Professional + 手动处理跨部门
    └── 是 → Enterprise
```

> 💡 **成本提示**: Enterprise 通常比 Professional 贵 40-70%。约 70% 的组织可以在 Professional 层面有效运营。

### 许可计费方式

HRSD 按 **HR Profile 表中的活跃用户数** 计费：
```
"An HR User is defined as any active User in the ServiceNow HR Profile table 
 that is within their employment start and end date, including full-time employees, 
 part-time employees, contractors, and contingent workers."
```

> ⚠️ **成本控制要点**: 
> - 确保及时清理已离职员工的 HR Profile
> - 外包临时工（如保洁、安保）如果不需要 HR 服务，不应创建 HR Profile
> - 额外订阅可能包括 Employee Center Pro 和 Document Management

## 1.5 产品演进路线（关键里程碑）

| 版本 | 日期 | 对 HRSD 的关键影响 |
|------|------|-------------------|
| **Vancouver** | 2023.09 | Now Assist for HRSD 首发（案例摘要、VA 聊天摘要） |
| **Utah** | 2024.03 | KB Generation、Sensitivity Detection、Enhanced VA Topics |
| **Nov 2024 Store** | 2024.11 | 知识块搜索、HCM 集成增强 |
| **Yokohama** | 2025.02 | Knowledge Graph for HR、VA 多模型支持、外部内容连接器 |
| **Mar 2025 Store** | 2025.03 | AI Agent Studio GA |
| **May 2025 Store** | 2025.05 | 4 个 OOB AI Agent、Orchestrator |
| **Xanadu** | 2025.05 | "The biggest ServiceNow AI release yet" |
| **Zurich** | 2025.09 | AI Control Tower、HRSD 重新打包（引入 Standard/Pro/Enterprise） |
| **Dec 2025 Store** | 2025.12 | Resolve HR Cases v3、Voice Agents v2 |
| **Mar 2026 Store** | 2026.03 | Hiring AI Agent、Voice Agents v3（8 语言） |
| **Zurich Patch 8** | 2026.05 | GPT-5.4、Claude Sonnet 4.6、Haiku 4.5 集成 |

> ⚠️ **升级提醒**: Zurich 版本对 HRSD 进行了重新打包（repackaging），如果从 Vancouver/Xanadu 升级，**必须重新验证所有许可配置**。

## ✅ 动手练习

### 练习 1：环境搭建
1. 登录你的 ServiceNow 实例，激活 `com.sn_hr_core` 插件
2. 确认当前应用范围为 "Human Resources"
3. 截图 HR Administration 菜单

### 练习 2：配置 HR 服务
1. 创建一个新的 COE: "Employee Relations"
2. 在该 COE 下创建 Topic Category: "Workplace Issues"
3. 创建 Topic Detail: "Harassment Complaint", "Conflict Resolution"
4. 为每个 Topic Detail 创建 HR Service（Fulfillment Type = Manual）

### 练习 3：案例路由
1. 创建一个 HR Skill: "Employee Relations Specialist"
2. 将技能分配给一个 Group
3. 创建一个 HR Case Template，绑定该 Group
4. 创建一个 Assignment Rule，将 Employee Relations 相关案例路由到该 Group

### 练习 4：选型决策
假设你是一家 3000 人公司的 HRSD 实施负责人，公司需求：
- 标准 HR 案例管理和知识库
- 员工自助门户
- HR 代理工作台
- 入职流程（仅 HR 内部处理，不需要 IT/设施参与）
- 未来计划部署 AI Agent

**问题**: 你会选择哪个 SKU？需要哪些附加许可？为什么？

## 附录：HRSD vs 传统 HRIS

### VS 传统 HRIS/HRMS

| 维度 | 传统 HRIS (Workday/SAP) | ServiceNow HRSD |
|------|------------------------|-----------------|
| 定位 | 人员数据权威源 (System of Record) | 服务交互层 (System of Engagement) |
| 核心 | 薪酬、考勤、招聘、绩效 | 案例、知识、自动化、AI |
| 用户 | HR 专业人员为主 | 全体员工 + HR 代理 |
| 集成 | 与 HRSD 双向同步 | 以 HCM 为数据源，做服务交付 |
