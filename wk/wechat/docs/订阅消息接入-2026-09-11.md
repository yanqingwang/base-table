## 一、做了什么（一句话）

把 P0-4 的**占位**提醒（`_send` 直接标 `sent`、不调微信）替换为**真实投递链路**：
扫描 → 校验订阅授权额度 → 调微信 `subscribeMessage.send` → 按微信 errcode 回写状态并扣减额度。

未配置小程序凭据时自动降级为演示（只落库、不真投），因此本地/演示站、既有 135 项测试全部不受影响。

## 二、投递流程与状态机

```
scan_reminders(merchant_id, force)
  └─ 逐张 active 卡判定：到期 / 余次 / 余额
       └─ _already_sent()  当天（同顾客+同场景+同卡）已记录过 → 跳过（force=True 绕过）
            └─ _deliver()
                 ├─ 未配置小程序凭据 ──────────→ status=sent  channel=demo  delivered=false
                 ├─ 场景未配模板 ID ───────────→ status=failed  reason=no_template
                 ├─ 授权额度 <= 0 ─────────────→ status=no_grant（不发，省一次无效请求）
                 └─ wechat_mps.send_subscribe_message()
                      ├─ errcode 0 ────────────→ status=sent    扣减 1 次授权
                      ├─ 43101 用户未订阅 ─────→ status=no_grant 授权清零
                      ├─ 40001/42001 token 失效 → 强制刷新 token 后**自动重试一次**
                      └─ 其他 ─────────────────→ status=failed  记录 errcode 与 reason
            └─ 落库 NotificationLog（payload 内嵌 channel / delivered / reason / errcode）
```

| status | 含义 | 顾客能否看到 | 商户侧提示 |
|---|---|---|---|
| `sent` + `delivered=true` | 微信已受理投递 | 是 | 已真实送达 |
| `sent` + `channel=demo` | 未配置凭据，仅落库 | 是 | 演示（未真投） |
| `no_grant` | 用户未订阅 / 额度已用完 | 是 | 用户未订阅 |
| `failed` | 模板未配 / 参数不合法 / 限频 / 网络 | 是 | 投递失败 |

**重要设计**：`failed` 与 `no_grant` **不扣减授权额度**，用户授权不会被白白消耗；但因按天去重，
当天不会重复尝试，**次日扫描会自动重试**，也可用 `force=true` 立即补发。

## 三、环境变量清单

| 变量 | 必填 | 默认 | 说明 |
|---|---|---|---|
| `WECHAT_MINI_APPID` | 是 | 回退 `WECHAT_APP_ID` | 小程序 AppID |
| `WECHAT_MINI_SECRET` | 是 | 回退 `WECHAT_APP_SECRET` | 小程序 AppSecret（**仅服务端**） |
| `WECHAT_TMPL_EXPIRE` | 是 | — | 到期提醒模板 ID |
| `WECHAT_TMPL_LOW_TIMES` | 是 | — | 余次提醒模板 ID |
| `WECHAT_TMPL_LOW_BALANCE` | 是 | — | 余额提醒模板 ID |
| `WECHAT_SUBSCRIBE_PAGE` | 否 | `pages/card/list/list` | 用户点提醒后跳转的小程序页 |
| `WECHAT_SUBSCRIBE_STATE` | 否 | `formal` | 跳转版本 `formal/trial/developer` |
| `WECHAT_SUBSCRIBE_PROXY` | 否 | 空 | 配置后走**代理模式**（云函数/网关代调微信），空则直连云 API |
| `WECHAT_SUBSCRIBE_FIELDS` | 否 | 内置映射 | JSON，覆盖模板字段映射（见下） |

> **两个必填变量都不配时不会报错**，系统降级为演示通道；只要 AppID + Secret 配好且模板 ID 齐全，
> 下一次扫描即自动切换为真实投递，**无需改代码、无需重启逻辑分支**。

### 默认模板字段映射

| 场景 | 默认 data | 业务字段来源 |
|---|---|---|
| 到期提醒 | `{"thing1": 商户名, "number2": 剩余天数, "date3": 到期日}` | merchantName / daysLeft / expireDate |
| 余次提醒 | `{"thing1": 商户名, "number2": 剩余次数}` | merchantName / remainingTimes |
| 余额提醒 | `{"thing1": 商户名, "amount2": 余额(元)}` | merchantName / balanceCents（自动分转元） |

字段名以**商户后台申请到的模板为准**。若模板字段不同，用一处 JSON 覆盖即可：

```bash
WECHAT_SUBSCRIBE_FIELDS='{"expire_reminder":{"thing1":"merchantName","date2":"expireDate"}}'
```

已内置的类型适配（避免微信 47003）：
- `thing` 超 20 字符自动截断（末尾加 `…`）
- `amount` 分 → 元，保留两位小数
- `date` 补全为 `yyyy-MM-dd HH:mm`（纯日期按当天 `23:59` 处理）
- payload 里缺失的字段**不会**造出空 value

## 四、小程序端接入片段（可直接粘贴）

> 本次**未修改** `card-counter-miniapp` 仓库（遵守"不影响原小程序"约束）。
> 以下片段按需合入 `pages/card/list/list.js` 或 `pages/profile/profile.js` 即可。

```js
// 1) 取订阅配置（模板 ID 是公开信息，接口不下发 AppSecret）
async function fetchSubscribeConfig() {
  const res = await wx.request({ url: `${API_BASE}/api/notifications/subscribe/config` });
  return res.data;                        // { configured, scenes:[{scene,label,templateId,ready}] }
}

// 2) 在「用户主动操作」时请求授权（必须是点击等用户手势里调用）
async function askSubscribe() {
  const cfg = await fetchSubscribeConfig();
  const tmplIds = (cfg.scenes || []).filter((s) => s.ready).map((s) => s.templateId);
  if (!tmplIds.length) return;            // 模板未申请，静默跳过

  wx.requestSubscribeMessage({
    tmplIds: tmplIds.slice(0, 3),         // 单次最多 3 个模板
    success: async (r) => {
      // r 形如 { errMsg, TMPL_EXPIRE: 'accept', TMPL_LOW_TIMES: 'reject' }
      const accepted = tmplIds.filter((id) => r[id] === 'accept');
      const scenes = (cfg.scenes || [])
        .filter((s) => accepted.includes(s.templateId))
        .map((s) => s.scene);
      if (!scenes.length) return;
      // 3) 上报已授权的场景 → 服务端记 1 次额度
      await wx.request({
        url: `${API_BASE}/api/notifications/subscribe`,
        method: 'POST',
        header: { 'Content-Type': 'application/json' },
        data: { scenes },
      });
    },
    fail: () => {},                       // 用户取消不阻断主流程
  });
}
```

**接入要点**
1. `wx.requestSubscribeMessage` **必须在用户点击手势中调用**，不能页面一进来就弹。
2. 不要保存 `accept` 就以为"以后都能发"——订阅是**一次性**的，每授权一次只能发一条。
3. 建议在「领取次卡成功」「查看卡详情」等高频真实场景里顺带请求授权，转化率最高。
4. 前端可用 `GET /api/notifications/grants` 显示"还可接收 N 条"，额度为 0 时再次引导授权。

## 五、后端接口

| 方法 | 路径 | 鉴权 | 说明 |
|---|---|---|---|
| GET | `/api/notifications/subscribe/config` | 公开 | 下发场景 + 模板 ID + 跳转页（**不含 Secret**） |
| POST | `/api/notifications/subscribe` | 顾客 | 上报已授权场景，`{"scenes":[...]}`，兼容 `accepted`/`scene` |
| GET | `/api/notifications/grants` | 顾客 | 自己的订阅额度（remaining/totalGranted/consumed） |
| GET | `/api/notifications` | 顾客 | 我的提醒列表（含 channel / delivered） |
| GET | `/api/merchant/notifications` | 商户 `view_report` | 本商户提醒记录（排查未送达，**不含 openid**） |
| POST | `/api/merchant/notifications/scan` | 商户 `view_report` | 本商户扫描推送，body `{"force":false}` |
| POST | `/api/platform/notifications/scan` | 平台超管 | 全租户扫描推送（定时器/补发用） |

## 六、微信错误码 → 内部状态映射

| errcode | 含义 | 内部 reason | status |
|---|---|---|---|
| 0 | 成功 | `ok` | `sent` |
| 43101 | 用户拒绝接收 / 未订阅 | `no_grant` | `no_grant`（授权清零） |
| 40001 / 40014 / 42001 / 40013 | access_token 无效 | `token_invalid` | 自动刷新重试一次 |
| 47003 / 41030 | 模板参数不合法 | `bad_param` | `failed` |
| 45009 / 45011 | 调用频率超限 | `rate_limited` | `failed` |
| 40003 | openid 不存在 | `user_not_found` | `failed` |

## 八、与生产仓 `card-counter-flask` 的关系

生产仓已有 `get_miniapp_access_token()` 与 `send_subscribe_message()`（走 CloudBase 云函数代理，
模板 ID 变量 `SUBSCRIBE_TEMPLATE_EXPIRING/REDEEM`，代理地址 `CLOUDBASE_SUBSCRIBE_URL`）。

本次在 commercial 的实现**沿用同一套 AppID 与错误处理策略**，并做了三点增强：

1. **默认直连**云 API（云托管容器可直接出网），同时保留 `WECHAT_SUBSCRIBE_PROXY` 兼容生产仓的代理形态；
2. token 缓存加**线程锁**（并发只刷新一次）+ 提前 5 分钟过期 + 失效自动重试；
3. 补齐**授权额度台账**（`SubscribeGrant`）与**错误码归一化**——生产仓当前只是"发完不管"，
   没有订阅额度概念，因此 43101 会静默失败。

**若要把这套能力回迁生产仓**，最小改动是：搬 `services/wechat_mps.py` + `SubscribeGrant` 模型
+ 把 `send_subscribe_message` 内部替换为 `wechat_mps.send_subscribe_message`。
