# 企业端多租户 · 门店层级 · 跨店消费（v3 方案）

**方案日期：2026-09-05**
**范围**：次卡管家「企业端」正式版的产品与技术基线（在 `card-counter-commercial` 演示仓先行实现自验，再随企业端小程序发布）

## 0. 已确认的产品决策（2026-09-05 与产品负责人对齐）
| # | 议题 | 决策 |
|---|------|------|
| D1 | 平台(租户)层入口 | **Web 后台**做平台超管（开通企业/授权管理员/停用）；企业端小程序只做“租户内”管理 |
| D2 | 企业内角色 | **授权管理员(可多人) → 门店 → 店长/店员** 三级；单店时管理员兼任店长 |
| D3 | 跨店池口径 | **混合**：默认同一张卡全店共享一个次数/余额池；部分产品可设“门店专属池” |
| D4 | 门店范围校验 | 发卡/核销/预约带“当前门店”，**仅模板允许的门店可操作**；顾客端展示卡可用门店 |

## 1. 分层架构

```
┌ 平台层 (Web 后台) ──────────────────────────────────────────┐
│  平台超管：新增“客户(=企业 Merchant)”、分配企业授权管理员、停用企业 │
└───────────────────────────────────────────────────────────┘
┌ 租户层（企业，Merchant）───────────────────────────────────┐
│  授权管理员(可多) → 管理门店与店员（建店/建店员/授权/停用）       │
│  单店：管理员即店长；多店：管理员管“门店集”，店长管各自门店        │
│    └ 门店 Store ─ 店长 StoreManager ─ 店员(按权限位)          │
│  产品(卡模板)：单店 / 全店共享池 / 指定门店共享 / 门店专属池       │
└───────────────────────────────────────────────────────────┘
┌ 顾客端（跨企业卡包）───────────────────────────────────────┐
│ 一个微信用户可持多家企业的卡；同一企业内跨店卡共享一池并显示可用门店 │
└───────────────────────────────────────────────────────────┘
```

## 2. 角色与权限
| 角色 | 层 | 能力 | 权限载体 |
|---|---|---|---|
| platform_admin | 平台 | 建企业、授权/停用管理员 | Web 后台（不入小程序） |
| merchant_admin（企业授权管理员，可多个） | 租户 | 建/停门店、建/停店员、配权限、看全店数据 | `Merchant.admins` |
| store_manager（店长） | 门店 | 该门店员工管理、排课/发卡/核销本店产品 | 角色=store_manager + 权限位 |
| clerk/staff（店员） | 门店 | 按权限位（发卡/核销/名单…） | `StaffRole.permissions` |
| 单店特例 | 租户 | admin == store_manager（同一人） | — |

权限位沿用：`issue_card / schedule / redeem / void_card / refund / manage_staff / view_report`；新增 `manage_store`（店长/管理员建改店）。

## 3. 数据模型增量（演示仓 models 为蓝本，向后兼容）
| 对象 | 改动 |
|---|---|
| `Merchant` | 加 `status=active/suspended`；`admins`(JSON: 授权管理员 staffId[]，由平台开通时写入) |
| `Staff` | 加 `storeId`(归属店，空=总部/平台)；保留 `roleId/isOwner`；`isOwner`=该企业首个 admin |
| `StaffRole` | 保留权限位；预置 `merchant_admin`(manage_store+manage_staff+全店 view_report)、`store_manager`、`clerk` |
| `MerchantStore` | 加 `managerStaffId`(店长)、`status`；门店 CRUD 仅 admin/store_manager 可 |
| `CardTemplate` | 加 `storeScope`: `single`(仅本店) / `shared`(默认：全店或指定门店共享一池) / `storeOnly`(门店专属池)；`allowedStoreIds`(JSON，`shared`+指定店时用，空=全店)；`poolMode`: `shared`/`split` |
| `Card` | 快照继承 `storeId/storeScope/poolMode`；核销记录归属门店 |
| `RedemptionRecord` | 加 `storeId`（split/门店专属池按店计次） |
| 顾客端 | 卡详情返回 `usableStoreIds/usableStoreNames`；跨企业分组展示不变 |

**混合池语义（D3）**
- `shared 全店/指定门店`：一张卡在全部门店（或 allowedStoreIds）**共享同一 used/held 计数**（现状即如此，仅需按店校验可核销性）。
- `split / storeOnly`：同一客户在同一企业不同门店各自发卡的“门店专属池”卡**独立计数**（卡级隔离，天然已支持）；若一张卡拆多店专属需 `TemplateStoreQuota`（按店额度）——建议先只做“卡级门店专属”，模板级额度拆分列为 M3 增强。

## 4. 门店范围校验规则（D4）
- **发卡**：默认按操作人门店写入 `Card.storeId`；`single/storeOnly` 模板仅本店可发；`shared` 模板任意允许门店可发。
- **核销/预约（消费端）**：请求带 `storeId`（=员工归属店）；校验 `卡.merchant == 员工.merchant` 且 `员工门店 ∈ 模板可用门店`；`single` 卡要求 `卡.storeId == 当前门店`，否则拒绝并提示“该卡仅限 XX 店使用”。
- **顾客端展示**：`/api/cards/mine` 聚合卡时按企业给出 `usableStores`；跨店共享池卡显示“可在 A/B 店使用”，单店卡仅显示本店。
- **管理员多店视角**：管理员/店长查卡、课次、名单默认限定其可见门店集（`?storeId=` 已支持；需补“可见门店集”默认注入）。

## 5. 接口增量草图（前缀 /api）
```
平台(Web 后台专用):
  POST/GET /api/platform/merchants            # 开通企业 + 授权管理员（platform token 校验）
  POST /api/platform/merchants/<id>/suspend

租户内(企业端小程序):
  GET  /api/merchant/tree                     # 管理员视角：门店→店长→店员树
  POST /api/merchant/staff                    # admin/store_manager 建店员(带 storeId/roleId)
  PATCH /api/merchant/staff/<id>/store        # 调店/授权（含 admin 多授权）
  GET  /api/merchant/stores/with-managers     # 门店+店长
  （storeScope/allowedStoreIds/poolMode）并入 create/update template、issue 参数
  redeem/booking/sessions 请求可选/必带 storeId（员工默认自动注入其归属店）
  GET  /api/cards/<id>/usable-stores          # 顾客端可见可用门店
```
