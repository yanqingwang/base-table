## 1. 本次交付

独立「商户端」小程序 MVP（与顾客端小程序分开），覆盖企业端核心操作：

| 页面 | 能力 | 对应接口 |
|---|---|---|
| 登录 | 演示身份（店长=全权限 / 核销员=仅核销），storage 存 merchantId/staffId | - |
| 工作台 | 次卡统计 + 快捷入口 + 未来7天课次 | GET /api/merchant/cards、/sessions |
| 发卡 | 选模板/姓名/生效方式(客户领取·立即生效)/自定义次数 → 展示领卡码 | POST /api/merchant/cards/issue |
| 次卡 | 列表（可用/总次/到期/状态）+ 销卡/延期30天 | void / extend |
| 核销 | 输入或 **扫一扫** 顾客动态核销码 → 扣次 | POST /api/merchant/redeem |
| 课次 | 未来30天课次；店长可**单节取消**；进名单 | sessions/cancel |
| 名单 | 签到 / 未到 / 取消预约 / 候补递补 | bookings checkin·no-show·cancel / waitlist promote |
| 我的 | 身份与权限展示、退出 | - |

架构要点：
- 复用已验证的后端契约（Web 演示端同一套 `/api/merchant/*`，camelCase + `X-Merchant-Id`/`X-Staff-Id`）；
- 发卡/核销等所有写操作带幂等 key，权限由后端兜底（核销员越权发卡实测 403）；
- 所有页面 data 字段与后端响应字段逐一对齐（自验 D 节）。

## 3. “不同企业的发卡绑定同一用户”（跨企业卡包）说明
- 数据层**已支持**：卡 = `merchantId` + `ownerCustomerId/ownerOpenid`，同一位顾客可持多家企业的卡；演示后端具备顾客端按企业聚合接口 `GET /api/my/merchants` + `GET /api/cards/mine`（“张女士同时持 商户1/商户3 两张卡、按企业分组”已过自动化测试）。
- 小程序落地路径（未在本次 MVP 内，见下节发布清单）：顾客端「我的次卡」按企业分组展示与切换。**依赖：把 my/merchants 移植到生产后端(flask-z9hh) + 顾客端小程序加分组 UI**，建议排 v2.8.0。
